# Агент управления рекламой: спецификация MCP

Назначение — дать ИИ-агенту доступ к рекламным кабинетам и статистике так,
чтобы он готовил отчёты и предложения сам, а расход менялся только по
решению владельца. Образец дисциплины — SMM-агент канала: публикация
только по нажатию владельца, расписание лишь готовит черновик.

Состояние: проект. Реализация — отдельным решением после теста: она
добавляет зависимости и токены доступа, а `CONTRIBUTING.md` требует
решения на каждую зависимость. API площадок, условия доступа и готовые
открытые серверы — `../research/04-площадки-и-правила.md`, раздел API.

## 1. Принципы

1. **Чтение свободно, запись через предложение.** Любое изменение
   оформляется предложением: что, где, было → станет, влияние на расход.
   Применяется только после подтверждения владельца. Подтверждение
   привязано к конкретному предложению и действует один раз.
2. **Потолок расхода в конфигурации сервера, а не в промте.** Месячный и
   недельный лимит по направлению задаёт владелец в конфигурации MCP;
   предложение сверх лимита сервер отклоняет до показа владельцу.
3. **Удалять нельзя.** Кампании, группы и объявления архивируются или
   останавливаются; удаление в набор инструментов не входит.
4. **Платёжные операции и реквизиты недоступны.** Пополнение, смена
   плательщика, данные маркировки — только владелец в интерфейсе площадки.
5. **Журнал.** Каждое чтение отчёта, предложение, подтверждение и
   применение пишется в журнал с временем и автором.
6. **Остановка по порогу** — единственное действие, которое может
   выполняться без подтверждения, и только если владелец включил его в
   конфигурации; по умолчанию выключено. Владелец получает сообщение сразу.

## 2. Инструменты

### Чтение

| Инструмент | Что возвращает | Источник |
|---|---|---|
| `campaigns_list` | кампании, состояние, стратегия, бюджет | Директ, Campaigns |
| `stats_report` | показы, клики, CTR, расход, цена клика, конверсии по цели `lead` — по кампании, группе, фразе, дню | Директ, Reports |
| `search_queries` | фактические поисковые запросы с показами и кликами | Директ, Reports (отчёт по поисковым запросам) |
| `goal_conversions` | достижения цели `lead` по источникам и страницам | Метрика, Reporting API |
| `leads_summary` | заявки по источнику-странице и состоянию за период, без персональных данных | кабинет, выгрузка руководителя |
| `keyword_frequency` | частотность фраз по регионам | Wordstat (если доступ есть) |

### Предложения (применяются после подтверждения)

| Инструмент | Что предлагает |
|---|---|
| `propose_negative_keywords` | минус-слова по результатам `search_queries` |
| `propose_bids` | изменение ставок или ограничения цены клика |
| `propose_budget` | изменение недельного бюджета в пределах лимита |
| `propose_ad` | новое объявление или правка текста (уходит на модерацию) |
| `propose_pause` / `propose_resume` | остановка или возобновление кампании, группы, фразы |
| `apply_confirmed` | применение подтверждённого предложения по его номеру |

## 3. Именование и метки

Кампания: `PD_{направление}_{канал}_{гео}_{вариант}_v{n}`, например
`PD_STU_SRCH_MSK-SPB_A_v1`, `PD_PG_SRCH_MSK-SPB_A_v1`. Направления: `STU` —
«Студентам», `PG` — «Аспирантам», `BIZ` — «Компаниям». Каналы: `SRCH` —
поиск, `RSYA` — сети, `RTG` — ретаргетинг, `AVITO`, `VK`, `TG`.

Группа: `{направление}_{группа семантики}`, например `STU_NORM`,
`STU_SUPPORT`, `PG_PREDEF`.

Метки ссылок: `utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}&utm_term={keyword}`
с подстановкой параметров Директа. Метки читает Метрика у посетителей,
согласившихся на статистику; с заявкой в базе они не сохраняются до
новой редакции согласия (Р-496).

## 4. Еженедельный цикл

1. Понедельник: агент снимает `stats_report`, `search_queries`,
   `goal_conversions`, `leads_summary` за прошлую неделю.
2. Пишет отчёт в `marketing/reports/ГГГГ-ММ-ДД.md` по шаблону.
3. Сверяет показатели с порогами выбранного варианта стратегии.
4. Формирует не больше пяти предложений с ожидаемым эффектом.
5. Владелец подтверждает или отклоняет каждое; агент применяет
   подтверждённые и дописывает итог в отчёт.

## 5. Предпосылки

- Доступ к API Директа выдаётся по заявке — подаётся сразу после открытия
  рекламного аккаунта, чтобы к концу теста доступ был.
- Отдельный токен Метрики только на чтение.
- Выгрузка заявок из кабинета без персональных данных: источник,
  состояние, даты.

## 6. Основа реализации

Официального MCP-сервера для Директа у Яндекса нет; открытые серверы —
любительские, 2026 года (`../research/04-площадки-и-правила.md`, 6.6).

| Кандидат | Что есть | Чего не хватает для этой спецификации |
|---|---|---|
| `Yurich-ru/yandex-ads-mcp` (MIT) | широкий набор операций Директа, режимы только чтения, подтверждения и песочницы | подтверждение — на стороне агента; нет потолка расхода в конфигурации и журнала подтверждений владельца |
| `artgas1/yandex-direct-mcp` | запись выключена по умолчанию | узкий набор операций |
| Собственный тонкий сервер | ровно инструменты раздела 2, потолки и журнал | разработка и сопровождение |

Рекомендация: открытый сервер в режиме только чтения для отчётов с
декабря; слой предложений и подтверждений (разделы 1–2) — собственный,
поверх него или отдельно. Выбор и подключение зависимостей — решением
владельца по `CONTRIBUTING.md`, после проверки кода выбранного сервера.
