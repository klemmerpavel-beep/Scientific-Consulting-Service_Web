# MCP-сервер Директа и Метрики — каркас

Собственный тонкий сервер по `../01-спецификация.md`, раздел 6:
инструменты раздела 2, потолки расхода в конфигурации и журнал. Без
новых зависимостей — Node 22 и его стандартная библиотека
(`CONTRIBUTING.md`, правило 5). Решение — Р-569.

Состояние: каркас проверен на заглушках API. К настоящему Директу не
подключён: нужен доступ к API (заявка — `../../launch/03-заявка-api-директа.md`).

## Что умеет

| Инструмент | Что делает |
|---|---|
| `campaigns_list` | кампании, состояние, дневной бюджет, направление по имени |
| `stats_report` | показы, клики, CTR, расход, цена клика по кампании, дню, группе или фразе; конверсии по цели `lead`, если цель задана |
| `search_queries` | фактические поисковые запросы — основа для минус-слов |
| `goal_conversions` | Метрика: визиты и цель `lead` по меткам и странице входа |
| `proposals_list` | предложения и их состояние |
| `propose_negative_keywords`, `propose_bids`, `propose_budget`, `propose_pause`, `propose_resume` | предложение изменения; сервер сверяет его с потолками и отправляет владельцу код |
| `apply_confirmed` | применение по коду владельца, один раз |

Удаления, пополнения, смены плательщика и данных маркировки в наборе нет.
Не вошли в каркас: `leads_summary` (нужна выгрузка заявок из кабинета без
персональных данных), `keyword_frequency` (Wordstat через Yandex Cloud),
`propose_ad` (новое объявление уходит на модерацию — пока вручную),
остановка по порогу.

## Как подтверждает владелец

1. Агент вызывает `propose_*`. Сервер проверяет потолки: ставку,
   дневной бюджет, расход месяца и недели по направлению. Лишнее
   отклоняется сразу, владельцу не показывается.
2. Сервер отправляет владельцу в Telegram: кампанию, что меняется,
   влияние на расход, причину и шестизначный код. Агенту — только номер
   предложения.
3. Владелец, если согласен, пишет агенту: «подтверждаю pr-0003, код …».
4. Агент вызывает `apply_confirmed`. Сервер сверяет код, заново проверяет
   потолки по текущей конфигурации и выполняет изменение.

Код одноразовый, живёт 72 часа, после пяти неверных попыток предложение
блокируется. В журнале — соль и отпечаток кода, самого кода нет.

**Граница защиты.** Код не даёт агенту применить изменение по ошибке или
по выдуманному «согласию». От агента, у которого есть оболочка на той же
машине и доступ к токенам, он не защищает: такой агент может вызвать API
напрямую. Поэтому на рабочем режиме сервер запускается от отдельного
пользователя ОС, а токены лежат в его окружении, недоступном агенту.

## Конфигурация

`config.json` рядом с сервером (в git не попадает), образец —
`config.example.json`. Правит владелец.

| Поле | Значение |
|---|---|
| `sandbox` | `true` — песочница Директа; на рабочий Директ переключает владелец |
| `write` | `false` — применение выключено целиком |
| `clientLogin` | логин клиента; для своего аккаунта не нужен |
| `apiVersion` | `v501` — по действующей документации; `v5` — прежние адреса |
| `metrika.counterId`, `metrika.goalId` | номер счётчика и цели `lead` |
| `metrika.attribution` | модель атрибуции для меток: `last`; «Последний значимый переход» Метрика отключила 20.05.2026. Проверить на первом живом запросе |
| `directions.STU`, `directions.PG` | потолки: `bidMax` — ставка, `dailyBudgetMax` — дневной бюджет, `weeklySpendMax` и `monthlySpendMax` — расход за 7 дней и календарный месяц, рубли без НДС |

Потолки образца — из `../../campaigns/direct-студенты.md` и
`../../campaigns/direct-аспиранты.md`. Ставку «Студентам» до 275 ₽ и
«Аспирантам» до 600 ₽ с 03.11 владелец поднимает правкой `bidMax`, а не
агент.

Токены — только в окружении:

| Переменная | Что |
|---|---|
| `DIRECT_TOKEN` | OAuth-токен с правом `direct:api` |
| `METRIKA_TOKEN` | OAuth-токен только с `metrika:read` |
| `MCP_TELEGRAM_BOT_TOKEN`, `MCP_TELEGRAM_CHAT_ID` | бот и чат владельца для кодов |
| `MCP_CONFIG` | путь к конфигурации, если не рядом с сервером |

## Подключение к Claude Code

```
claude mcp add prodisser-direct \
  -e MCP_CONFIG=/путь/к/config.json -e DIRECT_TOKEN=… -e METRIKA_TOKEN=… \
  -e MCP_TELEGRAM_BOT_TOKEN=… -e MCP_TELEGRAM_CHAT_ID=… \
  -- node /путь/к/marketing/mcp/server/server.mjs
```

Первый запуск — в песочнице с `write: false`: агент снимает отчёты,
владелец проверяет, что числа совпадают с интерфейсом Директа.

## Проверки

```
node --test "marketing/**/*.test.mjs"
```

Без сети: Директ, Метрика и Telegram заменены заглушками; отдельная
проверка запускает сервер и обменивается с ним сообщениями по stdio. CI
выполняет их на каждом запросе на слияние.
