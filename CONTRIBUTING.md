# Как вносить правки

Проект устроен не как обычное приложение на Next.js: страницы не пишутся
руками. Прочитайте этот файл до первой правки — иначе проверка в CI
гарантированно упадёт.

## Главное правило: правится макет, а не компонент

Источник правды по разметке и оформлению — файлы `design/*.dc.html`. Из них
конвертером `tools/dc-to-tsx.mjs` порождаются компоненты
`app/src/components/pages/*.tsx`. Эти компоненты **перезаписываются при каждом
переносе**, поэтому правка, внесённая прямо в `.tsx`, исчезнет и вдобавок
уронит сборку: CI переносит макеты заново и сверяет результат с тем, что
лежит в репозитории.

Соответствие восьми макетов и компонентов:

| Макет | Компонент | Маршрут |
|---|---|---|
| `design/StartPage.dc.html` | `StartPage.tsx` | `/` |
| `design/MainPage.dc.html` | **`PostgradPage.tsx`** | `/main` |
| `design/StudentsPage.dc.html` | `StudentsPage.tsx` | `/students` |
| `design/BusinessPage.dc.html` | `BusinessPage.tsx` | `/business` |
| `design/OfferPage.dc.html` | `OfferPage.tsx` | `/offer` |
| `design/PrivacyPage.dc.html` | `PrivacyPage.tsx` | `/privacy` |
| `design/ConsentPage.dc.html` | `ConsentPage.tsx` | `/consent` |
| `design/NotFoundPage.dc.html` | `NotFoundPage.tsx` | любой несуществующий адрес |

Обратите внимание на вторую строку: макет называется `MainPage`, компонент —
`PostgradPage`, а маршрут — `/main`. Это историческое расхождение, менять его
сейчас дороже, чем помнить.

Формат `.dc.html` и приёмы работы с ним описаны в `design/HANDOFF.md`.
Действующая дизайн-система — в `docs/DESIGN-SYSTEM.md`.

## Перенос макетов в код

После правки любого `design/*.dc.html` выполните из корня репозитория:

```bash
for t in "StartPage:StartPage:landing" \
         "MainPage:PostgradPage:postgrad" \
         "StudentsPage:StudentsPage:students" \
         "BusinessPage:BusinessPage:business" \
         "OfferPage:OfferPage:landing" \
         "PrivacyPage:PrivacyPage:landing" \
         "ConsentPage:ConsentPage:landing" \
         "NotFoundPage:NotFoundPage:landing"; do
  IFS=: read -r src name source <<< "$t"
  node tools/dc-to-tsx.mjs "design/$src.dc.html" \
    "app/src/components/pages/$name.tsx" "$name" "$source"
done
```

Полученные `.tsx` коммитятся вместе с макетом. Ровно эту же команду выполняет
CI, а затем требует `git diff --exit-code`.

## Что проверить до отправки

Из каталога `app/`:

```bash
npm run typecheck     # проверка типов
npm test              # проверки без базы, их же гоняет CI
npm run test:db       # то же вместе с проверками на PostgreSQL
npm run build         # рабочая сборка
npm run build:preview # статическая витрина
```

Автоматические проверки лежат в `app/tests/`: `npm test` — 2430 проверок
без базы, `npm run test:db` — 2669, из них 239 на настоящей PostgreSQL
(адрес базы из `app/.env`). CI выполняет `npm test` на каждом запросе на
слияние. Облик проверяется вручную и инструментально: axe-core на семи
страницах, переполнения на ширинах 360, 390, 414, 480, 768, 1024 и 1440 px
(`docs/DESIGN-SYSTEM.md`, раздел 6), отправка заявок со всех восьми форм,
обход клавиатурой. Снимки кабинета обходятся на 1100, 1280, 1440, 1920 и
390 px. Порядок описан в `docs/PLAN.md`, раздел 5.

Линтера в проекте нет намеренно: `next lint` объявлен устаревшим, а отдельная
настройка ESLint пока не заводилась.

## Правила, которые не обсуждаются в запросе на слияние

Они приняты решениями в `docs/DECISIONS.md` и обойти их правкой нельзя.

1. **Бэкенд не меняется правками вида.** Схема базы, миграции,
   `app/src/app/api/` и `app/src/lib/` трогаются только отдельным решением с
   явной причиной.
2. **Состав полей форм заморожен.** Поля, порядок, валидация, тексты галочек
   согласия и версия текста согласия менять нельзя: на них завязан журнал
   согласий по 152-ФЗ. Внешний вид формы менять можно.
3. **Юридические страницы** `/offer`, `/privacy`, `/consent` — только палитра
   и шрифты. Текст, нумерация разделов и даты редакций не меняются ни на
   символ: тексты согласованы юристом, пометка «Проект документа» снята
   решением Р-109 и не возвращается.
4. **Библиотеки анимации не подключаются** — решение Р-50. Движение задаётся
   средствами CSS.
5. **Зависимости не добавляются без отдельного решения.** Каждый новый пакет
   в производственной ветке — это поверхность цепочки поставок на проекте,
   который принимает персональные данные.

## Оформление запроса на слияние

Опишите, что изменилось и почему; приложите результаты проверок из раздела
выше. Если правка меняет облик страницы — приложите снимок до и после.
Решения по существу записываются в `docs/DECISIONS.md` отдельным пунктом:
там фиксируется разбор, а не только результат.
