# Кабинет: как им пользоваться

Короткое руководство для руководителя практики. Здесь — что делать руками,
а не как всё устроено внутри: устройство описано в `CABINET.md`, решения —
в `DECISIONS.md`.

Адрес: **https://prodisser.ru/cabinet**

---

## 1. Вход

Пароля нет. Вход по одноразовой ссылке: она действует час и срабатывает
один раз.

Пока почта `info@prodisser.ru` не заведена, письмо отправлять некуда, и
ссылка выдаётся командой на сервере:

```bash
cd /opt/prodisser
docker compose --env-file deploy/.env -f deploy/docker-compose.yml \
  --profile tools run --rm tools scripts/grant-role.ts \
  ваш@адрес HEAD "Клеммер Павел Сергеевич"
```

Та же команда нужна, когда ссылка просрочена: она выдаёт новую, а не
заводит вторую учётную запись.

Когда почта появится, порядок станет обычным: на странице входа вводится
адрес, ссылка приходит письмом.

**Выход** — кнопка «Выйти» в шапке. Сессия закрывается на всех страницах.

## 2. Что где

Меню кабинета, слева направо:

| Раздел | Для чего |
|---|---|
| **Сводка** | заявки, сроки, непрочитанные сообщения — главный экран |
| **Работы** | все проекты практики |
| **Деньги** | договоры, поступления, вознаграждения, итоги по годам |
| **Аналитика** | шесть вкладок: обзор, деньги, клиенты, продукты, проекты, потери |
| **Уведомления** | куда вам сообщать о событиях |

Разделы руководителя, доступные по прямым адресам: пользователи
(`/cabinet/manage/users`), справочники (`/directory`), перенос книги
заказов (`/import`), журнал действий (`/audit`), очередь отправки
(`/outbox`), удаление данных по требованию (`/erasure`).

## 3. Заявка → работа

Заявки с сайта попадают в «Сводку», раздел **«Заявки на рассмотрении»**.
Очередь листается по двадцать; первыми идут самые давние. Сверху видно,
сколько всего: «Всего 258 заявок, показаны с 1 по 20».

В карточке заявки видно: страница сайта, дата, отметка о согласии, имя и
контакт заявителя, что человек написал.

**Одобрить.** Заполняете «Название проекта», выбираете тип сопровождения
(кандидатская, статья, диплом, НИР, пакет аспирантуры, консалтинг),
при желании отмечаете «Применить шаблон этапов этого типа» — и нажимаете
«Одобрить и создать проект».

Дальше происходит само:

- заводится работа с номером вида `PD-2026-001`;
- заводится учётная запись клиента на тот адрес, что он оставил;
- вы становитесь куратором работы;
- если у типа заведён шаблон, этапы создаются сразу (шаблоны — в
  справочнике «Типы сопровождения»).

**Отклонить.** Пишете причину — её увидит заявитель, поэтому формулировка
человеческая, — и нажимаете «Отклонить».

## 4. Ведение работы

Карточка работы: **Работы** → выбрать нужную. На ней четыре части.

**Ход работы.** Этапы со сроками и состояниями. Кнопка «Добавить этап»
заводит новый. Внутри этапа — перевод состояния: в работе, ждём клиента,
на проверке, завершён. Клиент видит эти состояния у себя.

**Материалы.** Файлы работы с версиями: каждая новая загрузка не затирает
предыдущую, а становится следующей версией. Эксперт оставляет замечания к
версии, вы решаете, показывать их клиенту или нет.

**Переписка с клиентом.** Сообщения по работе. Сообщение с телефоном или
почтой помечается: контакты в обход системы — повод посмотреть внимательно.

**Оплаты и документы.** Договор (номер, дата, сумма), поступления
траншами, вознаграждение эксперта, закрывающие документы. Здесь же видно
маржу по работе.

## 5. Деньги

**Деньги → Договоры и расчёты.** Пять плиток сверху: законтрактовано,
получено, к получению, потери, маржа. Ниже — то же по каждой работе.

**Деньги → Итоги по годам.** Таблица по годам, где рядом стоят две
величины: **введённая вами** и **посчитанная кабинетом**. Форма внизу:
год, выручка, расходы, заметка. Повторный ввод того же года заменяет
строку.

Колонка «расхождение» показывает разницу. Пока история прошлых лет ведётся
в вашей книге, а через кабинет проходит только новое, расхождение большое —
это нормально. Оно уменьшается по мере того, как работы идут через кабинет;
дойдёт до нуля — отдельная книга больше не нужна.

Выручка года считается по дате оплаты. У перенесённых из книги заказов
поступлений даты оплаты нет — в книге её не вели, — поэтому они отнесены к
году по дате договора; подпись под таблицей говорит, сколько таких.

---

## 6. Люди

**Пользователи** (`/cabinet/manage/users`): завести учётную запись, сменить
роль, приостановить доступ.

Роли: клиент, эксперт, менеджер, руководитель. Менеджер ведёт свои работы и
не видит ни маржи, ни вознаграждений экспертам. Эксперт видит только
назначенные работы и своё вознаграждение — переписки с клиентом у него нет.

**Реестры** (`Сводка` → «Клиенты и эксперты»): кто есть кто, с контактами.

## 7. Что пока не работает

Честный перечень на сегодня:

- **Письма не уходят.** Ящик `info@prodisser.ru` не заведён: уведомления
  копятся в очереди отправки. Клиент не получит ни приглашения в кабинет,
  ни сообщения о смене этапа.
- **Telegram не подключён.** Нужен бот и два значения в настройках сервера.
- **Таблица заявок на Диске выключена.** Ждёт тариф Яндекса для
  организаций и пункт об облачном хранилище в Политике.

Всё три закрываются покупкой Яндекс 360 для организаций: там и почта на
домене, и хранилище с договором.

---

## 8. Если что-то пошло не так

- **Ссылка входа не работает.** Она одноразовая и живёт час — выдайте новую
  той же командой.
- **Экран отвечает «страница не найдена».** Работа чужая либо её нет:
  менеджер видит только свои работы, это не сбой.
- **Уведомление не дошло.** Раздел «Очередь отправки» показывает
  недоставленное с причиной.
- **Сайт не отвечает.** Проверка `https://prodisser.ru/api/health` должна
  отвечать `{"ok":true,"db":true}`. Если нет — напишите мне, разберу по
  журналам.
