# Как купить хостинг и опубликовать сайт

Инструкция для владельца. Все действия выполняются вами, доступы остаются
у вас: ни пароля, ни ключа никому передавать не нужно.

Домен `prodisser.ru` уже зарегистрирован в Рег.ру, DNS-серверы —
`ns1.hosting.reg.ru` и `ns2.hosting.reg.ru`. Домен переносить никуда не надо:
он остаётся там, где есть, и просто начинает указывать на новый сервер.

Порядок: сначала сервер, потом почта, потом DNS, потом публикация.
На всё уходит один вечер, из которого половина — ожидание DNS.

---

## Что именно покупается

Три вещи, две из них платные.

| Что | Где | Сколько в месяц |
|---|---|---|
| Облачный сервер (VPS) — на нём и сайт, и база | Timeweb Cloud | ~880–950 ₽ |
| Внешний адрес IPv4 к серверу | там же | ~190 ₽ |
| Почта `info@prodisser.ru` | Рег.ру, тариф Mail‑1 | 0 ₽ |
| Домен `prodisser.ru` | Рег.ру | уже оплачен |

**Отдельную «базу данных» покупать не надо.** PostgreSQL ставится на тот же
сервер вместе с сайтом — так уже настроено в `deploy/docker-compose.yml`.
Управляемая база у провайдера стоит ещё 700–900 ₽ в месяц и на этом объёме
не даёт ничего: заявок на сайте единицы в день, а держать данные в одном
месте проще и для резервного копирования, и для объяснения проверяющему.
Выносить базу отдельно имеет смысл, когда появятся кабинет и админ-панель
и одной машины станет мало.

Итого около 1100 ₽ в месяц. Это чуть выше названного вами ориентира
в 1000 ₽: конфигурация 1 ГБ дешевле, но на ней не соберётся образ
приложения — замеры в `docs/DEPLOY.md`, раздел 1.

## Шаг 1. Выбрать площадку

**Рекомендация: Timeweb Cloud, конфигурация «Cloud MSK 40» —
2 vCPU / 2 ГБ / 40 ГБ NVMe, регион Москва.**

Почему он:

- В реестре хостинг-провайдеров Роскомнадзора. Это не пожелание, а условие:
  размещаться у провайдера вне реестра с декабря 2023 года нельзя.
- Почасовая тарификация. Можно поднять сервер, проверить, что сайт
  открывается, и погасить — заплатив за несколько часов.
- Серверы в Москве и Петербурге. Требование ч. 5 ст. 18 152-ФЗ:
  база с данными граждан России физически в России.
- Понятная панель без лишнего.

Равноценные варианты, если Timeweb почему-то не подойдёт:

| Провайдер | Цена 2 ГБ | Замечание |
|---|---|---|
| **Selectel** | ~940 ₽ | инфраструктура крупнее, панель сложнее |
| **Beget** | дешевле | проще, меньше настроек |
| **Рег.ру** (VDS SSD‑2) | ~1190 ₽ | всё в одном кабинете с доменом, но дороже |

Вариант «всё у Рег.ру» удобен тем, что счёт и панель одни. Он дороже
примерно на 300 ₽ в месяц — если эта разница вам не важна, берите его,
техническая разница между площадками для нашей задачи нулевая.

**Цены обязательно перепроверьте на день покупки.** С 1 января 2026 года
Рег.ру поднял цены, Timeweb и Selectel поднимали в конце 2025 — начале 2026
на 8–20 %. Цифры выше — ориентир, а не оферта.

**Чего не делать.** Не брать зарубежный VPS, Vercel, Netlify, Hetzner,
DigitalOcean — никакие. И **не ставить Cloudflare** перед сайтом: он
пропускает трафик и расшифровывает его на своих серверах за границей,
а это ровно та трансграничная передача, которой раздел 9 нашей политики
не допускает. Отдельная ловушка: бесплатный Cloudflare выглядит как
безобидное «ускорение», и о нём легко забыть при заполнении уведомления
Роскомнадзора.

### Что сделать до оплаты — это важнее выбора тарифа

1. Откройте [реестр хостинг-провайдеров РКН](https://rkn.gov.ru/activity/connection/register/p1578/),
   найдите провайдера (Timeweb — АО «ТаймВеб»), **сохраните снимок экрана
   с датой**. Это ваше доказательство добросовестности, если когда-нибудь
   спросят, почему выбран именно он.
2. Оформляйте договор **на ООО «РУСДРОН»**, а не на физическое лицо.
   Политика (раздел 8) говорит, что обработка поручается третьим лицам
   на основании договора с обязанностью соблюдать конфиденциальность.
   Договор с частным лицом этому не соответствует, и закрывающих
   документов для бухгалтерии тоже не будет.
3. Скачайте и сохраните договор-оферту провайдера. Найдите в нём раздел
   про персональные данные и конфиденциальность — он там есть у всех
   четверых. Этот файл понадобится, если Роскомнадзор запросит основание
   поручения обработки.
4. **Выпишите наименование и юридический адрес провайдера.** Их нужно
   будет внести в раздел 8 политики (шаг 10).

## Шаг 2. Создать сервер

В панели Timeweb Cloud: «Облачные серверы» → «Создать».

| Параметр | Значение |
|---|---|
| Регион | Москва |
| Образ | Ubuntu 24.04 LTS |
| Конфигурация | 2 vCPU / 2 ГБ / 40 ГБ NVMe |
| Публичный IPv4 | включить (платный, ~190 ₽/мес) |
| Доступ | **SSH-ключ**, не пароль |

Про ключ. Если ключа нет, сделайте его на своём компьютере:

```bash
ssh-keygen -t ed25519 -C "prodisser"
cat ~/.ssh/id_ed25519.pub
```

Содержимое второй команды (одна строка, начинается с `ssh-ed25519`)
вставляется в панель. Файл `id_ed25519` без `.pub` — секретный, его никуда
не отправляют и не показывают. Вход по паролю подбирают роботы в первые же
часы после создания сервера; вход по ключу — нет.

После создания панель покажет IP-адрес вида `92.51.xx.xx`. Запишите его —
он понадобится на шаге 5.

## Шаг 3. Первый вход и подготовка

```bash
ssh root@ВАШ_IP
```

Обновление и файл подкачки (без него не соберётся образ приложения —
сборке нужен пик около гигабайта, а памяти всего два):

```bash
apt update && apt upgrade -y
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

Межсетевой экран — открыты только три порта:

```bash
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
```

Порт базы `5432` наружу **не открывается**: приложение и база общаются
внутри Docker, снаружи к базе доступа быть не должно.

Docker:

```bash
curl -fsSL https://get.docker.com | sh
docker --version && docker compose version
```

```bash
apt install -y git

cd prodisser
```

Дальше — по `docs/DEPLOY.md`, раздел 4: заполнить `deploy/.env` по образцу

## Шаг 5. Направить домен на сервер

Домен остаётся в Рег.ру, меняются только записи в его зоне.

Кабинет Рег.ру → «Домены» → `prodisser.ru` → вкладка «Управление» →
«DNS-серверы и зона» → «Изменить».

DNS-серверы `ns1.hosting.reg.ru` и `ns2.hosting.reg.ru` **оставляем как есть** —
зона правится прямо здесь.

Добавить или исправить две записи типа **A**:

| Тип | Имя | Значение |
|---|---|---|
| A | `prodisser.ru` (или `@`) | IP сервера из шага 2 |
| A | `www.prodisser.ru` (или `www`) | тот же IP |

Если в зоне уже есть записи A с этими именами, указывающие на парковку
Рег.ру, — **исправьте их, а не добавляйте вторые**. Две записи A на одно
имя означают, что половина посетителей попадёт на старый адрес.

Изменения расходятся от часа до суток. Проверить с любого компьютера:

```bash
dig +short prodisser.ru
dig +short www.prodisser.ru
```

Обе команды должны показать IP вашего сервера. Пока показывают старое —
сертификат выпускать рано, он не выдастся.

## Шаг 6. Почта на домене

Ящик `info@prodisser.ru` **обязателен**: этот адрес уже напечатан в оферте,
политике и согласии как единственный контакт оператора. Сайт откроется
с ним в текстах, и письмо на несуществующий ящик — это невыполнение
собственного документа.

В Рег.ру есть бесплатный тариф **Mail‑1**: до 1000 ящиков, 10 ГБ.
Кабинет → «Почта» → «Почта на домене» → выбрать `prodisser.ru` → Mail‑1.

Рег.ру сам добавит в зону нужные записи **MX**, **SPF** (`TXT` с
`v=spf1 …`) и **DKIM**. Проверьте, что они появились, и **не удаляйте**
их при правке записей A из шага 5 — это разные записи, они уживаются
в одной зоне. Без SPF и DKIM письма с сайта будут падать в спам.

Заведите два ящика:

- `info@prodisser.ru` — тот, что в документах, для людей;
- `site@prodisser.ru` — от него сайт отправляет письма о заявках.

Реквизиты SMTP из панели Рег.ру впишите в `deploy/.env`:

```
SMTP_HOST=mail.hosting.reg.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=site@prodisser.ru
SMTP_PASSWORD=пароль_ящика
SMTP_FROM=ProDisser <site@prodisser.ru>
LEAD_MAIL_TO=info@prodisser.ru
```

Хост уточните в панели — у Рег.ру он может отличаться от указанного.
Проверить, что ящик отправляет письма, можно прямо с сервера, ещё до
публикации сайта:

```bash
printf 'From: site@prodisser.ru\nTo: info@prodisser.ru\nSubject: Proverka\n\nProverka\n' > /tmp/m.txt
curl --url "smtps://mail.hosting.reg.ru:465" --ssl-reqd \
  --mail-from "site@prodisser.ru" --mail-rcpt "info@prodisser.ru" \
  --upload-file /tmp/m.txt --user "site@prodisser.ru:ПАРОЛЬ_ЯЩИКА"
rm /tmp/m.txt
```

Команда завершается молча, если письмо ушло, и печатает ошибку, если нет.
Письмо должно прийти на `info@prodisser.ru` — проверьте и папку «Спам».

## Шаг 7. Telegram (по желанию)

Канал необязательный. В мессенджер приходит только сигнал: страница,
форма, время и номер заявки — без имени, контакта и темы работы.
Так сделано намеренно (`docs/DECISIONS.md`, Р‑52): Telegram работает
на серверах за пределами России, и отправка туда содержания заявки была
бы трансграничной передачей, которой наша политика не допускает.

Токен берётся у `@BotFather`, идентификатор чата — у `@getidsbot`,
оба вписываются в `deploy/.env`. Если оставить поля пустыми, приём
заявок работает как обычно: заявка сохраняется в базе и приходит на почту.

## Шаг 8. Запуск, сертификат, расписания

Всё это — `docs/DEPLOY.md`, разделы 3а и 4. Коротко о порядке:

1. Накатить схему базы, потом собрать и запустить:

   ```bash
   docker compose --env-file deploy/.env -f deploy/docker-compose.yml \
     --profile migrate run --rm migrate
   docker compose --env-file deploy/.env -f deploy/docker-compose.yml \
     up -d --build
   ```

   Порядок важен: без схемы приложению некуда писать заявки.
2. Поставить nginx и выпустить сертификат: `certbot --nginx -d prodisser.ru -d www.prodisser.ru`.
   Сертификат выдаётся только после того, как DNS из шага 5 разошёлся.
3. Приложение **обязательно** работает за nginx и никогда напрямую
   в интернет — иначе адрес заявителя в журнале согласий можно подменить
   заголовком запроса.
4. Два задания в `crontab -e`:

```
0 3 * * * /opt/prodisser/deploy/backup.sh >> /var/log/prodisser-backup.log 2>&1
30 3 * * 1 /opt/prodisser/deploy/retention.sh >> /var/log/prodisser-retention.log 2>&1
```

Первое снимает копию базы, второе удаляет заявки старше года, по которым
не заключён договор, — это исполнение пункта 7.1 политики. Второе задание
обязательно: обещание в тексте без исполнения в коде проверяется одним
запросом к базе.

Резервные копии остаются на сервере в России. Выгружать их в зарубежное
хранилище нельзя — копия это та же обработка персональных данных.

## Шаг 10. Что сделать сразу после покупки

Это не техника, но без этого запуск неполный.

1. **Внести наименование и адрес провайдера в раздел 8 политики.**
   Состав сведений в согласии по закону включает наименование и адрес
   лица, обрабатывающего данные по поручению оператора. Сейчас там
   написано, что эти сведения предоставляются по запросу, — так можно
   до покупки, но не после. Правка вносится в `design/PrivacyPage.dc.html`
   и переносится конвертером; напишите мне, я сделаю за пять минут.
2. **Подать уведомление в Роскомнадзор** — до открытия сайта, не после.
   В графе о трансграничной передаче указывается «не осуществляется»:
   условие выполнено, пока хостинг и почта российские, а в Telegram
   уходит сигнал без персональных данных. Подключите зарубежный ящик,
   счётчик посещаемости или верните содержание заявки в мессенджер —
   и графа станет ложной, а уведомление придётся подавать заново.
3. Сохранить в одну папку: договор с провайдером, снимок реестра РКН
   с датой, подтверждение подачи уведомления. Это весь пакет, который
   спрашивают при проверке.

## Если что-то пошло не так

| Симптом | Причина, которая встречается чаще всего |
|---|---|
| Сайт не открывается, `dig` показывает старый адрес | DNS ещё не разошёлся; ждать до суток |
| `certbot` не выдаёт сертификат | DNS не разошёлся, либо закрыт порт 80 |
| Сборка падает без внятной ошибки | нет файла подкачки, кончилась память (шаг 3) |
| `{"ok":true,"db":false}` | не поднялась база или неверный пароль в `deploy/.env` |
| Заявка не приходит на почту | неверный `SMTP_HOST`; проверить командой из шага 6 |
| Письма падают в спам | в зоне нет записей SPF и DKIM (шаг 6) |
| Место кончилось | `docker system prune -f` — Docker копит старые слои |
