# Клиент и личный кабинет: что реализовано

Состояние на 03.10.2026. Основание — код ветки `main` репозитория
`scientific-consulting-service_web`, коммит `24f36f2`, с доработками по
требованиям `client-cabinet-requirements.md`; выполненные требования
перечислены в разделе 17. Пути к файлам даны от `app/src/`.

**Названия ролей** приведены к решению В-12 (требование Э-01; решения
Р-321, Р-322): «менеджер» — роль `MANAGER`, менеджер работы; «куратор» —
роль `EXPERT`, исполнитель со степенью. В прежней редакции описания
«куратор» означал менеджера, а «эксперт», «исполнитель» и «специалист» —
куратора.

**Назначение документа.** Документ описывает только то, что уже работает на
боевом сервере (https://prodisser.ru/cabinet). Это исходная точка для
постановки требований: в конце каждого раздела оставлено поле
«Требования», его заполняет разработчик. Отдельно, в разделе 15, собраны
места, где поведение кабинета расходится с ожидаемым или не доведено до
конца; по ним нужно решение.

Условные обозначения:

- «Клиент» — учётная запись с ролью `CLIENT`.
- «Менеджер» — менеджер, за которым закреплена работа.
- «Куратор» — куратор-куратор.
- «Руководитель» — роль `HEAD`.

## 1. Сквозной путь клиента

```
Заявка на сайте ──┐
                  ├─► разбор заявки менеджером ─► одобрение ─► работа PD-… + учётная запись клиента
Заявка из кабинета┘                         └─► отказ ─► письмо заявителю с причиной
                                                      │
                                                      ▼
   письмо «Заявка принята: работа PD-…» (без ссылки входа)
                                                      │
                                                      ▼
   вход: адрес почты → письмо со ссылкой → кнопка «Войти»
                                                      │
                                                      ▼
   «Мои работы» → карточка работы → этап
        ├─ приложить материалы (этап «Ждём ваших данных»)
        ├─ посмотреть версии и замечания, оставить комментарий
        ├─ согласовать этап (этап «На согласовании»)
        └─ переписка с менеджером
                                                      │
                                                      ▼
   уведомления о событиях — почта и (по желанию) Telegram
```

## 2. Права клиента

Единственная точка решения о доступе — `lib/cabinet/access.ts`. Права
проверяются на сервере, а не скрытием элементов интерфейса.

| Действие | Клиент | Условие |
|---|---|---|
| Видеть работу, её этапы и историю | да | только своя работа |
| Видеть и скачивать материалы | да | только своя работа |
| Загружать материалы | да | только своя работа |
| Оставлять комментарии к версиям материалов | да | только своя работа |
| Согласовать этап | да | только своя работа, этап «На согласовании», работа в действии |
| Вернуть этап с замечаниями | да | там же; текст замечаний обязателен (Р-281) |
| Читать и писать в переписку | да | только своя работа; собеседник — менеджер и руководитель |
| Видеть договор и оплаты | да | только своя работа; ссылка — на карточке работы (раздел 9) |
| Подать заявку из кабинета | да | — |
| Менять этапы, сроки, состояния | нет | — |
| Модерировать замечания | нет | — |
| Видеть контакты, маржу, вознаграждение куратора | нет | этих полей нет в данных, которые получает экран |
| Писать куратору напрямую | нет | прямого канала клиент ↔ куратор нет |

Чужая работа отвечает «страница не найдена», так же как несуществующая.
Её существование по адресу не угадать.

**Куратор и менеджер для клиента — без имён.** Куратор подписан
«Куратор» при любой роли в работе, менеджер и руководитель — «Менеджер»:
в авторах версий, в комментариях, в переписке, в истории. Имён и
контактов сотрудников нет ни на экране, ни в данных экрана; строки
«куратор — …» и события «Назначен куратор» клиенту не показываются
(Р-277, Р-321, Р-322).

## 3. Как клиент появляется в системе

| Путь | Учётная запись | Согласие на обработку ПДн | Письмо клиенту |
|---|---|---|---|
| Заявка с сайта, одобрена менеджером | создаётся при одобрении, если в заявке есть почта | переносится из заявки: момент и редакция согласия | «Заявка принята: работа {код}» — что такое кабинет и как войти; ссылки входа в письме нет |
| Повторная заявка того же человека | уже есть | уже есть | «Заведена новая работа {код}» |
| Заявка из кабинета (раздел 10) | уже есть | спрашивается в форме, если его ещё нет | как выше |
| Заказ, заведённый вручную («Новый заказ»), или перенос книги заказов | не создаётся | — | писем нет; вход открывает руководитель отдельно, на экране «Учётные записи» |

Сразу после заявки с почтой заявителю уходит письмо «Заявка получена — ProDisser»
(Р-312): менеджер разберёт заявку и ответит в течение рабочего дня, решение
придёт письмом; контакты практики; «Если вы не оставляли заявку, удалите
это письмо». Без имени, темы и ссылок. Отзыву, заявке с телефоном и
машинной заявке письма нет; на один адрес — не больше письма в сутки;
не ушедшее за сутки письмо не отправляется.

При отказе по заявке заявителю уходит письмо с причиной. Заявке, которую
приём пометил как машинную (спам), письма нет. Повторный отказ второго
письма не отправляет.

Ссылку входа в письмо об одобрении не кладут намеренно. Ссылка живёт
15 минут, а письмо может пролежать в очереди дольше, и к моменту прочтения
ссылка была бы уже мёртвой.

Учётная запись создаётся только при известной почте: вход возможен лишь по
ссылке на почту. Если почта заявки принадлежит сотруднику или закрытой
записи, работа на неё не вешается.

Источники: `lib/cabinet/projects.ts`, `lib/cabinet/manual-order.ts`.

## 4. Вход и сессия

**Вход без пароля, по одноразовой ссылке.**

1. Страница `/cabinet`: заголовок «Личный кабинет», поле «Электронная почта»
   и кнопка «Прислать ссылку»; под формой — «Ещё не работаете с нами?
   Оставить заявку» на форму заявки сайта (Р-313).
2. Ответ на запрос всегда одинаковый, есть такой адрес или нет: «Если адрес
   зарегистрирован, письмо уже отправлено. Ссылка действует 15 минут.
   Проверьте папку «Спам». Прислать ещё раз можно через минуту» и кнопка
   «Прислать ещё раз» с тем же адресом (Р-313). По ответу нельзя узнать,
   зарегистрирован ли адрес.
3. Ссылка из письма действует **15 минут** и срабатывает **один раз**.
4. Открытие ссылки ведёт на экран с кнопкой «Войти» и замаскированным
   адресом владельца ссылки. Ссылка гасится только нажатием кнопки, поэтому
   предпросмотр в мессенджерах и почтовые проверщики ссылок её не тратят.
   Подпись на экране: «Если это не ваш адрес, не нажимайте «Войти»: ссылку
   выдали на чужую почту». Устаревшая, использованная или поддельная
   ссылка после «Войти» даёт «Ссылка устарела или уже использована» и
   кнопку «Прислать новую ссылку»: новая уходит владельцу старой, с тем же
   путём возврата, адрес не показывается, ответ один для любой ссылки
   (Р-313).
5. Ссылку можно получить и не по почте: её выдаёт руководитель на экране
   «Учётные записи». Такая ссылка действует 2 часа и тоже срабатывает один
   раз; передаётся лично.
6. **«Открыть кабинет» из письма и сигнала** (Р-309). Кнопка письма ведёт
   на `/cabinet/open` с экраном события и адресом получателя. С открытой
   сессией человек сразу попадает на экран события. Без сессии адрес и
   экран кладутся в cookie на 10 минут, человек попадает на чистый
   `/cabinet` с готовым адресом в поле; после «Прислать ссылку» и «Войти»
   в письме входа — на экран события, в том числе с другого устройства:
   путь хранится в токене входа. Путь — только внутри кабинета; ссылка
   входа в письмо о событии не кладётся (Р-162). Любой экран без сессии
   ведёт тем же путём и возвращает на себя после входа.

**Ограничения на запрос ссылок**, окно — 1 час:

- не чаще одной ссылки в минуту на адрес, с любых узлов (Р-313);
- не более 5 ссылок на пару «адрес + IP»;
- не более 10 на один адрес со всех IP вместе;
- не более 20 запросов с одного IP на любые адреса.

Потолок в 10 ссылок на адрес не действует на IP, с которого владелец уже
входил.

**Сессия:**

- живёт 30 дней и продлевается при обращениях;
- абсолютный предел — 90 дней от входа, затем нужна новая ссылка;
- cookie сессии `HttpOnly`;
- кнопка «Выйти» в шапке закрывает сессию.

**Если почтовый канал не настроен,** страница входа говорит: «Вход по ссылке
пока недоступен: отправка писем ProDisser ещё не настроена. Напишите
менеджеру работы — он откроет доступ другим способом».

Источники: `app/cabinet/page.tsx`, `app/cabinet/enter/[token]/page.tsx`,
`lib/cabinet/auth.ts`, `lib/cabinet/token.ts`.

## 6. «Мои работы»

**Ответ сверху — что от клиента нужно сейчас.**

| Ситуация | Текст | Кнопка |
|---|---|---|
| Этап ждёт материалов | «От вас ждут материалы к этапу «…».» + срок этапа + «Работа «…» стоит, пока их нет.» + «Ещё дел за вами: N» | «Открыть этап» |
| Этап на согласовании | «От вас ждут согласования этапа «…».» + «Срок согласования — до {дата} включительно.» (Р-290) + «Работа «…» продолжится после вашего согласования.» | «Открыть этап» |
| Дел нет, работы идут | «Сейчас от вас ничего не требуется — работа идёт.» + ближайший срок этапа или «Срок этапа «…» прошёл …» | — |
| Действующих работ нет | «Действующих работ нет.» + «Заявку на сопровождение новой работы можно оставить здесь же.» | «Новая заявка» |

**Одна работа — сразу карточка** (Р-311). «Мои работы» и вход ведут
клиента прямо на карточку работы, если работа у него одна, она действует
или приостановлена, блок первого входа закрыт и в адресе нет отбора
(`?state=`, `?q=`, `?page=`). Иначе — перечень. На карточке подсвечен пункт
«Мои работы».

**Блок первого входа «Как устроен кабинет»** (Р-310) — под ответом, пока
клиент его не закрыл: «Что от вас нужно — в верхней строке «Моих работ» и
на карточке работы», «Материалы прикладываются на экране этапа или в
«Материалах работы»», «Менеджеру пишите в переписке на карточке работы».
Кнопка «Подключить Telegram» — если бот настроен и Telegram ещё не
подключён; «Понятно» закрывает блок навсегда для учётной записи
(`User.welcomeClosedAt`).

**Перечень работ:**

- при числе работ больше 8 появляются вкладки «Действующие», «Ждут меня»,
  «Завершённые», «Все» и поиск;
- в строке работы — что ждут по этапу («Загрузить материалы: …»,
  «Согласовать этап: …»);
- у работы — счётчик непрочитанных сообщений.

Источник: `app/cabinet/projects/page.tsx`.

## 7. Карточка работы

Адрес `/cabinet/projects/{код}` (`app/cabinet/projects/[code]/page.tsx`).

**Шапка.** Название работы и «срок — {дата}». Пометка состояния
появляется, только если работа не в действии: «Приостановлена»,
«Завершена», «Отменена». Код работы клиенту не показывается.

**Телефон** (Р-320). Ниже 1024 px карточка складывается в одну колонку:
сначала главная фраза и план работ, затем переписка, затем «История
работы». Свёртки «О работе» и «История» растут по содержимому — вложенной
прокрутки нет; на 360 px горизонтальной прокрутки нет.

**Свёртка «О работе»:**

- «Тип сопровождения» — скрыт, если совпадает с названием;
- «Тема» — скрыта, если совпадает с названием;
- «Срок работы» — дата или «не назначен»;
- строки «Менеджер» у клиента нет: имя менеджера клиенту не показывается
  (Р-321);
- «Куратор» — степень и шифр специальности, без ФИО и контактов; роль
  куратора в работе клиенту не выводится; пустые части не выводятся
  (Р-297, Р-322);
- краткое описание задачи (поле, которое ведёт менеджер).

**Шкала готовности:**

- процент — доля завершённых этапов;
- текущий этап — первый незавершённый: строка «где работа»;
- главная фраза — ход клиента на любом этапе, тем же перечнем, что у «Моих
  работ»: «От вас ждут материалы к этапу «…»» или «…согласования этапа
  «…»», срок, «Ещё дел: N», кнопка «Открыть этап» (Р-287). У
  приостановленной работы — «Работа приостановлена — сейчас от вас ничего
  не требуется». Прежние варианты по состоянию первого этапа:
  - ждёт материалов — «От вас нужны материалы или данные — откройте этап и
    приложите их.» и кнопка «Открыть этап»;
  - на согласовании — «Этап готов и ждёт вашего согласования: посмотрите
    материалы и подтвердите.» и кнопка «Открыть этап»;
  - иначе — «Сейчас от вас ничего не требуется — работа идёт.»;
  - этапов нет — «План работ составляет менеджер — этапы появятся здесь.»;
  - работа закрыта — «Работа закрыта. Материалы остаются доступны здесь.»;
- под шкалой — «N из M этапов завершено», срок этапа, срок работы и
  пометка «прошёл».

**Колонка «План работ»:**

- у каждого этапа — название (ссылка на экран этапа), состояние, срок,
  пометка «срок прошёл», краткое описание (две строки);
- в состоянии «Ждём ваших данных» — причина, указанная менеджером;
- над планом — ссылки «материалы · N» и «Оплаты и документы».

**Колонка «Переписка с менеджером»:**

- последние 8 сообщений;
- поле «Написать менеджеру» и кнопка «Отправить»;
- ссылка «вся переписка» или «вся · N новых».

**Свёртка «История работы»:**

- смена состояния этапов, приостановка, завершение, отмена и возобновление
  работы, новые версии материалов, взятие работы в сопровождение, смена
  менеджера;
- документы оплат — «Приложен счёт к траншу «…»», «Приложен акт к траншу
  «…»», «Приложен договор»; события о документах скрытых траншей не
  показываются (Р-315);
- авторы событий — «Вы», «Менеджер», «Куратор» (Р-321, Р-322);
- согласование этапа названо по способу: «согласован вами», «согласован
  менеджером по вашему подтверждению: {основание}», «принят по истечении
  срока согласования (п. 7.3 оферты)» (О-6, Р-292);
- назначение куратора скрыто.

**Не видно клиенту:** управление работой, куратор, контакты, суммы из
книги заказов.

## 8. Этап: материалы, комментарии, согласование

### 8.1. Состояния этапа глазами клиента

Подписи — `lib/cabinet/stage-state.ts`.

| Состояние | Подпись у клиента | Подпись у сотрудников | Чей ход |
|---|---|---|---|
| `NOT_STARTED` | Не начат | Не начат | практики |
| `IN_PROGRESS` | В работе | В работе | практики |
| `AWAITING_CLIENT` | Ждём ваших данных | Ждёт материалов клиента | клиента: приложить материалы |
| `IN_APPROVAL` | На согласовании | На согласовании у клиента | клиента: согласовать |
| `DONE` | Завершён | Завершён | — |

Переводит этап между состояниями только практика. Исключение — согласование
клиентом. На согласование этап уходит, только если к нему приложен хотя бы
один материал и менеджер написал итог этапа: что сделано и что дальше
(Р-289).

### 8.2. Экран этапа

Адрес `/cabinet/stages/{id}` (`app/cabinet/stages/[id]/page.tsx`).

**Шапка:** название этапа, состояние, «срок — {дата} · прошёл N дней
назад». Под шапкой — описание этапа целиком (Р-286); если этап ждёт данных
клиента — причина, указанная менеджером.

**Согласование.** Карточка показывается, если этап «На согласовании» и
работа в действии:

- заголовок «Этап ждёт вашего согласования»;
- итог этапа под подписью «Итог этапа: что сделано и что дальше» —
  над кнопками (Р-289);
- срок: «Согласовать до {дата} включительно (по московскому времени).»
  При включённом автозакрытии — «Если до этой даты вы не согласуете этап и
  не вернёте его с замечаниями, он считается принятым — п. 7.3 оферты»,
  при выключенном — «Срок — по п. 7.2 оферты»; ссылка ведёт на
  `/offer#delivery` (Р-290). Срок — пять рабочих дней (или число,
  заданное для работы) со дня, следующего за сдачей; на паузе работы он
  стоит, после возврата и повторной сдачи считается заново. После срока при
  включённом автозакрытии согласовать или вернуть этап нельзя: «Срок
  согласования истёк {дата}: этап принят по п. 7.3 оферты»;
- текст «Посмотрите последнюю версию материалов и комментарии. После
  согласования этап закрывается, и работа переходит к следующему.»;
- кнопка «Согласовать этап»: этап переходит в «Завершён»;
- свёртка «Вернуть с замечаниями»: поле «Что исправить или дополнить»
  обязательно; этап уходит «В работу» с пометкой «Возвращён с замечаниями
  {дата}», текст виден под шапкой этапа и в истории работы. Куратор видит
  текст, только если в нём нет контактов (Р-281).

**Материалы и версии:**

- «Материалы и версии»: у каждой версии номер «v{n}», автор, дата, размер и
  кнопка «Скачать»; версия куратора видна клиенту после публикации
  менеджером — до неё её нет ни в перечне, ни по прямой ссылке, а письмо
  «Новая версия материала» и строка истории приходят при публикации (Р-294);
  материал, у которого нет ни одной видимой версии, не показывается (Р-295);
- «Загрузить следующую версию» — к существующему материалу;
- «Приложить новый материал» — название и файл. Подсказка: «Каждая
  загрузка сохраняется отдельной версией: прежние остаются доступными»;
- в завершённый этап файлы и комментарии клиента не принимаются: вместо
  форм — «Этап завершён. Если нужно передать файл, напишите менеджеру»; у
  завершённой и отменённой работы — «Работа закрыта. Если нужно передать
  файл, напишите менеджеру». Правило держит сервер, а не только экран
  (Р-293).

**Комментарии к версиям:**

- поле «Оставить комментарий» — только под последней версией материала;
- комментарий клиента публикуется сразу. Если в тексте есть телефон, почта
  или ссылка на мессенджер, комментарий уходит на проверку менеджеру, а
  клиент видит у него пометку « · ожидает публикации»;
- замечание куратора клиент видит только после того, как менеджер его
  опубликует;
- не опубликованный менеджером комментарий клиента помечен « · не
  опубликовано менеджером», с причиной;
- длина комментария — до 10 000 знаков.

### 8.3. Экран «Материалы работы»

Адрес `/cabinet/projects/{код}/materials`.

- Все материалы работы: название, привязка к этапу («этап N: …» или «вне
  этапов»), число версий.
- У каждой версии: имя файла (ссылка на скачивание), размер, дата, автор,
  число замечаний. Текст замечаний — на экране этапа; у материала вне
  этапов — здесь же, под версиями (Р-284).
- «Загрузить следующую версию».
- «Приложить материал»: название, этап («без привязки к этапу» или этап,
  который не завершён), файл. У закрытой работы форм нет (Р-293).
- Документы оплат (счета, акты, договор) здесь не показываются.

## 9. Оплаты и документы

Адрес `/cabinet/projects/{код}/payments`
(`app/cabinet/projects/[code]/payments/page.tsx`).

Клиент открывает экран ссылкой «Оплаты и документы» в шапке «Плана работ»
на карточке работы, рядом с «материалы · N»; письмо о смене статуса
платежа ведёт сюда же (Р-280).

Что на нём видит клиент:

- договор: номер и дата; если договора нет — «Договор ещё не заведён.»;
- «Сумма договора», «Корректировка суммы» (если не ноль), «Получено»,
  «Осталось оплатить»: «Сумма договора − Корректировка − Получено =
  Осталось оплатить» сходится и при списанной части, и у отменённой работы
  (Р-315). У действующей работы под корректировкой — «сумма к оплате
  изменена по договорённости»; оплачено больше договора — строка «Оплачено
  сверх суммы договора» (ОМ-30);
- у отменённой работы — «Работа отменена {дата}» под «Осталось оплатить»
  (без даты — у работ из книги без даты закрытия);
- полоса «Оплачено N % суммы договора»;
- «Транши»: название, срок, дата оплаты, состояние («ожидается»,
  «выставлен счёт», «оплачен»), сумма; к траншу приложены ссылки «счёт: …»
  и «акт: …»;
- «Документы по договору»: файл договора.

Что скрыто от клиента:

- списанные и сторнированные транши — их нет в выборке;
- сумма списанного, маржа, вознаграждение куратора — этих полей нет в
  данных экрана; корректировка — вычисляемая величина, а не «списано»;
- кнопки изменения: деньги ведёт только руководитель; загружать документы
  оплат клиент не может.

## 11. Переписка с менеджером

Адрес `/cabinet/projects/{код}/messages` (`lib/cabinet/messages.ts`).

**Участники:** клиент с одной стороны, менеджер работы и руководитель — с
другой. Куратор в переписке не участвует: это технический барьер против
ухода клиента к куратору в обход практики.

**Экран:**

- подзаголовок «с менеджером · {ФИО}»;
- сообщения сгруппированы по дням, у каждого — автор и время, свои
  сообщения подписаны «Вы»;
- поле «Новое сообщение» с подсказкой «Переписка ведётся внутри кабинета:
  она остаётся при работе и доступна обеим сторонам»;
- под полем — ссылка «Файлы прикладывайте в материалах работы» и
  заготовки «Попросить созвон» («Прошу созвониться по работе. Удобное
  время: ») и «Попросить перенести срок этапа» («Прошу перенести срок этапа
  «{текущий этап}» на . Причина: »). Заготовка открывает тот же экран с
  текстом в поле; отправляет только «Отправить»; набранный до выбора
  заготовки текст не сохраняется (Р-316).

**Ограничения:**

- до 10 000 знаков;
- пустое сообщение не отправляется;
- вложений в переписке нет: файлы — через материалы.

**Прочтение:** открытие экрана переписки отмечает сообщения практики
прочитанными. Клиент видит счётчик новых сообщений, а под своим
сообщением рядом со временем — «· прочитано менеджером», когда менеджер
работы его прочитал; сотрудникам отметка не показывается (П-07, Р-399).

**Контакты в тексте.** Сообщение с телефоном, почтой, `@именем` или ссылкой
на t.me, wa.me, vk.com не блокируется. Практика видит у него пометку
«похоже на передачу контактов», а сообщение попадает в реестр «Контакты в
переписке». Клиент пометки не видит.

## 12. Настройки: «Как сообщать о ходе работы»

Заголовок экрана — «Настройки», подзаголовок — «Как сообщать о ходе
работы» (Р-314).

Адрес `/cabinet/settings` (`app/cabinet/settings/page.tsx`,
`lib/cabinet/channels.ts`).

**«Как с вами связываться».** Предпочтения для менеджера; сами звонки и
сообщения система не делает.

- Над перечнем — отдельная отметка «Полное сопровождение» с кнопкой
  «Сохранить»: менеджер ведёт работу сам и связывается первым, не
  дожидаясь вопросов. Это порядок работы, а не способ связи: в перечне
  его нет, предпочтительным он не бывает; менеджер видит в блоке клиента
  строку «Просит полное сопровождение» (П-09, Р-401).
- Способы связи:
  - «Письмо на почту»;
  - «Сообщение в Telegram»;
  - «Звонок менеджера»;
  - «Мессенджер или социальная сеть».
- У способа — номер или ссылка и оговорка («звонить после 18:00»).
- Один способ можно отметить предпочтительным; кнопки «Сделать основным»
  и «Убрать».

**«Куда слать уведомления»:**

- флажки «Электронная почта — {адрес}» (включена по умолчанию) и
  «Telegram»;
- выбрать Telegram можно только после привязки аккаунта;
- свёртка «Что и когда отправлено» — двадцать последних своих
  уведомлений, новые сверху: тема, день и время по Москве, канал
  («письмо», «Telegram») и исход («отправлено», «в очереди на отправку»,
  «отправка назначена», «не отправлено: канал отключён», «не доставлено»
  и т. д.); текста письма в перечне нет. Перечень есть у каждой роли и
  показывает только свои строки (П-04, Р-402).

**Привязка Telegram:**

- кнопка «Подключить Telegram» открывает бота; клиент нажимает в нём
  «Начать»;
- ссылка привязки действует час и срабатывает один раз; войти по ней в
  кабинет нельзя;
- кнопка «Отвязать»;
- если бот не настроен на стороне сервиса: «Канал не настроен… Пока
  уведомления приходят только почтой».

**«Удаление персональных данных».** Отметка «Прошу удалить мои
персональные данные» и кнопка «Отправить запрос»: требование ложится на
экран руководителя «Удаление данных», руководителям — письмо. Пока
требование не исполнено, вместо формы — «Запрос отправлен {дата}…»;
повторный запрос не принимается. Договоры и платёжные документы, которые
закон обязывает хранить, сохраняются (П-08, Р-400).

**Согласие.** Внизу экрана — дата принятия согласия на обработку ПДн и
строка «Отозвать его и потребовать удаления данных можно письмом
менеджеру или на info.prodisser@gmail.com» — адрес ссылкой `mailto` из
`practice-contacts.ts`; до нового адреса на домене — адрес действующих
правовых текстов (О-7, Р-314). Бот в ответах называет раздел «Настройки».

Выбирать каналы отдельно по каждому событию могут только сотрудники;
клиенту эта таблица не показывается.

## 13. Уведомления клиенту

Механизм — очередь отправки (`lib/cabinet/outbox.ts`). Каналы — почта и
Telegram (если привязан и включён).

- Письмо несёт тему и текст.
- В письме — кнопка «Открыть кабинет» на экран события: этап, материалы,
  переписку, оплаты или карточку работы (Р-309).
- Сообщение в Telegram — только сигнал: «ProDisser · {событие} · {код
  работы}. Подробности в кабинете: …» — ссылка на экран события, без адреса
  почты.
- Текст переписки наружу не пересылается ни одним каналом.

| Событие | Когда | Тема письма |
|---|---|---|
| Работа открыта | одобрена заявка | «Заявка принята: работа {код}» / «Заведена новая работа {код}» |
| Состояние работы | приостановлена, завершена, отменена, возобновлена | «Работа «…» приостановлена» (с причиной), «…завершена» (материалы остаются доступны), «…отменена» (с причиной), «…возобновлена» (Р-299) |
| Новый менеджер | работу передали другому менеджеру | «У работы «…» новый менеджер» — имя, степень, специальность (Р-299) |
| Этап ждёт материалов | этап переведён в «Ждём ваших данных» | «Этап «…» ждёт ваших материалов» (с причиной) |
| Этап на согласовании | этап переведён в «На согласовании» | «Этап «…» готов к согласованию» (с итогом этапа, Р-289) |
| Новая версия материала | материал загрузила другая сторона | «Новая версия материала: …» |
| Замечание куратора | менеджер опубликовал замечание куратора | «Куратор оставил замечание по материалу» |
| Состояние платежа | транш заведён, выставлен счёт, оплачен | «Статус платежа изменился: …» — со ссылкой на экран оплат работы (Р-280) |
| Новое сообщение | написал менеджер или руководитель; повторно не шлётся, пока прежнее не прочитано | «Новое сообщение по работе {код}» (без текста) |
| Срок этапа подходит | этап ждёт ваших данных, до срока 3 дня, работа в действии; одно письмо на срок (Р-301) | «Срок этапа «…» — {дата}» |
| Срок этапа сорван | этап ждёт ваших данных, срок прошёл вчера; одно письмо (Р-301) | «Срок этапа «…» сорван» |
| Срок этапа изменён | менеджер перенёс срок этапа, у которого срок был | «Срок этапа «…» изменён» — новый срок и причина (Р-302) |
| Срок согласования подходит | за один рабочий день до последнего дня срока согласования; одно на срок | «Согласуйте этап «…» до {дата}» (Р-290) |
| Срок согласования назначен | этап стоял на согласовании без срока: при выкате или после того, как менеджер открыл вход | «Срок согласования этапа «…»» с датой (Р-290) |
| Этап принят по сроку | срок согласования истёк при включённом автозакрытии | «Этап «…» принят» — по п. 7.3 оферты (Р-290) |
| Заявка получена | заявка с почтой принята сайтом (не отзыв и не машинная); одно в сутки на адрес; годно сутки (Р-312) | «Заявка получена — ProDisser» |
| Отказ по заявке | менеджер отклонил заявку | письмо заявителю с причиной |

Клиенту **не** сообщается:

- переход этапа в «В работе» и «Завершён»;
- приостановка, завершение и отмена работы;
- смена менеджера;
- отклонение его комментария;
- списание и сторно транша.

Письма уходят, когда на сервере настроена почта. До того они копятся в
очереди и не теряются. Исключение — напоминание о сроке: не отправленное за
сутки, оно закрывается без отправки, чтобы клиент не получил «срок через три
дня» после срока (Р-278). Ответ на письмо кабинета уходит на адрес
`MAIL_REPLY_TO`, если он задан.

## 14. Файлы: ограничения и хранение

Источники — `lib/cabinet/materials.ts`, `lib/cabinet/storage.ts`,
`app/cabinet/files/[versionId]/route.ts`.

**Ограничения:**

| Что | Значение |
|---|---|
| Размер файла материала | до 50 МБ; пустой файл не принимается |
| Тип файла | исполняемые файлы и установщики (exe, msi, bat, cmd, com, scr, vbs, ps1, jar, apk и подобные) не принимаются — по расширению и по содержимому; отказ: «Файл «…» не принят: исполняемые файлы и установщики загружать нельзя. Если файл нужен для работы, напишите менеджеру» (Р-296) |
| Файлы заявки | до 5 файлов по 25 МБ |
| Типы файлов | ограничений нет |
| Проверка содержимого (антивирус) | нет |
| Имя файла и название материала | не должны содержать телефон, почту или ссылку на мессенджер; иначе отказ с объяснением на экране |

**Версии.** Неизменяемы: каждая загрузка — новая версия, прежние остаются.

**Хранение:**

- на сервере, в каталоге `CABINET_STORAGE_DIR`;
- имя файла в путь хранения не попадает;
- для каждой версии считается контрольная сумма sha256.

**Скачивание:**

- только через проверку прав;
- каждое скачивание пишется в журнал доступа к файлам;
- файл отдаётся вложением с исходным именем;
- опасные для браузера типы (HTML, SVG, JS) отдаются как двоичный поток;
- если сохранить файл не удалось, клиент видит причину: «Файл не сохранён:

## 15. Расхождения и незавершённые места

Ниже — наблюдения по коду, не исправленные на 03.10.2026. По каждому
нужно решение: исправить или оставить как есть.

1. **Нет ссылки на «Оплаты и документы».**
   - Экран для клиента реализован, но кнопка на карточке работы
     показывается только сотрудникам (`projects/[code]/page.tsx`, строка
     ≈841, условие `!forClient`).
   - Письмо о смене статуса платежа при этом говорит «Документы и
     состояние оплат видны в кабинете».
   - Нужно решение: давать клиенту ссылку или убрать экран и фразу из
     письма.
2. **Загрузка не учитывает состояние работы.**
   - Клиент может приложить файл к приостановленной, завершённой или
     отменённой работе.
   - Через экран «Материалы работы» — и к завершённому этапу.
   - С экрана этапа приложить новый материал к завершённому этапу нельзя.
3. **Комментарий не учитывает состояние.** Комментарий к версии можно
   оставить при любом состоянии этапа и работы.
4. **Нет «вернуть на доработку».**
   - На этапе «На согласовании» у клиента одна кнопка — «Согласовать
     этап».
   - Несогласие выражается только комментарием или сообщением менеджеру.
5. **О согласовании этапа практике не сообщается.** Менеджер узнаёт о нём
   из кабинета.
6. **Шкала готовности смотрит только на первый незавершённый этап.**
   - Если ход клиента нужен на более позднем этапе, на шкале его нет.
   - В перечне «Мои работы» и на экране этапа он виден.
7. **Описание этапа не выводится на экране этапа.** Оно видно на карточке
   работы, в две строки.
8. **Файлы куратора не проходят модерацию.**
   - Модерируются только замечания куратора.
   - Загруженные им файлы клиент видит и скачивает сразу; проверяются
     лишь имя и название на контакты.
9. **История работы и документы оплат.** Загрузка счёта или акта даёт в
   истории строку «Приложена версия N материала» без названия.
10. **Списанный транш не объяснён.** Если транш списан, «Сумма договора −
    Получено» не равна «Осталось оплатить», а пояснения у клиента нет.
11. **Отменённая работа на экране оплат.** «Осталось оплатить» равно 0, а
    пояснение «работа отменена» видит только руководитель.
12. **Отзыв согласия и удаление данных — только письмом менеджеру.**
    - Кнопки в кабинете нет.
    - Исполняет удаление руководитель на экране «Удаление данных
      субъекта».
13. **Нет антивирусной проверки и ограничения типов файлов.**
14. **Нет вложений в переписке и отметки «прочитано» для клиента.**
15. **Учётная запись клиента при ручном заказе и переносе книги не
    создаётся.** Доступ открывает руководитель вручную.
16. **Почта и Telegram зависят от настроек сервера.** Пока почтовый ящик
    на домене и бот не настроены, клиент не получает ни писем, ни ссылки
    входа по почте. Порядок настройки — `docs/RELEASE.md`, часть 4.1.
