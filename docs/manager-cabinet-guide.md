# Менеджер и личный кабинет: что реализовано

Состояние на 03.10.2026. Основание — код ветки `main` репозитория
`scientific-consulting-service_web`, коммит `24f36f2`, с доработками по
требованиям `manager-cabinet-requirements.md`; выполненные требования
перечислены в разделе 17. Пути к файлам даны от `app/src/`.

**Назначение документа.** Документ описывает только то, что уже работает на
боевом сервере (https://prodisser.ru/cabinet) для роли «менеджер»
(`MANAGER`). Это исходная точка для постановки требований: в конце
каждого раздела оставлено поле «Требования», его заполняет разработчик.
Места, где поведение расходится с ожидаемым или не доведено до конца,
собраны в разделе 15. Парный документ — `client-cabinet-guide.md` (то же
для клиента).

**Условные обозначения:**

- «Менеджер» — учётная запись `MANAGER`.
- «Куратор работы» — менеджер, за которым закреплена работа
  (`project.managerId`).
- «Руководитель» — роль `HEAD`.
- «Специалист» — эксперт-исполнитель (`EXPERT`).

---

## 1. Роль менеджера в одном абзаце

Менеджер:

- разбирает очередь заявок практики;
- одобряет заявку в работу, после чего становится её куратором, либо
  отказывает с причиной;
- заводит заказы вручную;
- ведёт свои работы: план этапов, сроки, состояния, исполнитель, переписка
  с клиентом, модерация замечаний.

Чужие работы менеджер не видит. Чего у менеджера нет:

- денежного контура: только просмотр оплат своих работ, без маржи и
  вознаграждений;
- аналитики, журналов, учётных записей, справочников, переноса книги
  заказов, удаления данных;
- права передавать работы между кураторами.

Всё перечисленное — у руководителя.

## 2. Права менеджера

Единственная точка решения о доступе — `lib/cabinet/access.ts`. Права
проверяются на сервере. Перечни сужаются выборкой `scopeProjects` до
условия `{ managerId: actor.id }`.

| Действие | Менеджер | Условие |
|---|---|---|
| Видеть работу, её этапы, историю, материалы | да | только работы, где он куратор |
| Править карточку работы, этапы, сроки, состояния этапов | да | там же; этапы — только у работы в действии |
| Менять состояние работы (приостановить, завершить, отменить, возобновить) | да | там же |
| Назначать исполнителя | да | там же |
| Согласовать этап за клиента | да | там же; этап «На согласовании», работа в действии |
| Модерировать замечания специалиста и клиента | да | там же |
| Переписка с клиентом | да | там же |
| Видеть контакты клиента | да | там же и в реестре своих клиентов |
| Смотреть договор и оплаты | да, только просмотр | там же |
| Разбирать заявки (одобрить, отказать, статус, комментарии) | да | все неразобранные заявки практики и заявки, ставшие его работами |
| Заводить заказ вручную | да | куратором становится сам менеджер |
| Реестры | да | клиенты — только по своим работам; эксперты — все |
| Передать работу другому куратору | нет | только руководитель |
| Менять договор и транши, видеть маржу и вознаграждения | нет | только руководитель |
| Учётные записи сотрудников | нет | только руководитель |
| Открыть клиенту вход в кабинет | да | только клиенту своей работы: кнопка в блоке «Клиент»; запись по почте карточки, ссылка на 2 часа; руководитель получает уведомление (Р-285) |
| Справочники, шаблоны этапов, перенос книги заказов | нет | только руководитель |
| Аналитика, отчёт за период, деньги практики | нет | только руководитель |
| Журналы, очередь уведомлений, зеркало на Диске, удаление данных | нет | только руководитель |

Чужая работа на любом экране и при скачивании файла по прямой ссылке
отвечает «страница не найдена». Служебные экраны руководителя
перенаправляют менеджера на «Работы практики».

## 3. Вход и меню

**Вход** — тот же, что у всех ролей: одноразовая ссылка на почту. Ссылка
действует 15 минут, гасится кнопкой «Войти». Сессия живёт 30 дней,
абсолютный предел — 90 дней. Подробно — в `client-cabinet-guide.md`,
раздел 4.

- Ссылку вручную выдаёт руководитель — любому, и куратор — клиенту своей
  работы, кнопкой «Открыть клиенту вход» на карточке работы (Р-285). Ручная
  ссылка действует 2 часа; выдача новой гасит прежние.
- После входа менеджер попадает на «Работы практики»
  (`/cabinet/projects`).

**Меню** (`lib/cabinet/nav.ts`):

| Пункт | Адрес | Назначение |
|---|---|---|
| Требует внимания | `/cabinet/manage` | дела на сегодня по своим работам и очередь заявок |
| Работы | `/cabinet/projects` | перечень своих работ |
| Управление | `/cabinet/manage/tools` | служебные разделы: менеджеру доступны три |
| Уведомления | `/cabinet/settings` | способы связи, каналы, правила уведомлений, Telegram |

## 4. «Требует внимания» — рабочий экран

Адрес `/cabinet/manage` (`app/cabinet/manage/page.tsx`). Заголовок экрана —
«Работа на сегодня».

**Ответ сверху:**

- «Сегодня ничего не горит.» или «N дел требуют решения.»;
- «Сорвано сроков этапов и работ — N; старший — «…», N дней.»;
- «N заявок ждут разбора.»;
- кнопка «Начать с главного» открывает первое дело.

**Блок «Требует внимания · N»** — только по работам, где менеджер куратор:

| Вид дела | Пометка | Что сделать | Сколько показывать при > 12 дел |
|---|---|---|---|
| Сорванный срок этапа | «просрочено N дней» + чей ход | «Назначить новый срок или перевести этап» | 4 |
| Сорванный срок работы (без сорванного этапа; в том числе приостановленной) | «срок работы прошёл N дней назад» | «Назначить новый срок, завести план или закрыть работу» / «Возобновить с новым сроком или закрыть работу» | 2 |
| Этап ждёт клиента дольше 14 дней | «ждёт клиента с {дата}» | «Напомнить клиенту о материалах» | 2 |
| Непрочитанные сообщения клиента | «N непрочитанных» | «Ответить клиенту» | 3 |
| Замечания на модерации | «N замечаний на модерации» | «Опубликовать или отклонить — до этого клиент их не видит» | 3 |
| Клиент вернул этап с замечаниями (Р-283) | «клиент вернул с замечаниями {дата}» | «Разобрать замечания и отметить «Замечания приняты в работу»» — кнопка на экране этапа; дело уходит и при новой сдаче | 3 |

Толщина и цвет полоски слева растут с давностью просрочки. Когда дел
больше 12, каждого вида показано несколько первых, а кнопка «Показать все
N» раскрывает весь перечень.

**Ниже два блока:**

- **«Мои работы · N»** — название, клиент и этап, «срок работы — дата ·
  прошёл». Денег нет.
- **«Заявки · N»** — очередь неразобранных заявок практики, старые сверху,
  по 20; у каждой кнопка «Разобрать».

**Менеджеру не показываются:**

- плитки практики;
- графики «Заказы по месяцам», «Чем занята практика», «Что заказывают»;
- блок «Ближайшие сроки и деньги»;
- кнопка «Отчёт за период»;
- суммы «не получено» в делах.

## 5. Заявки

### 5.1. Перечень «Все заявки»

Адрес `/cabinet/manage/leads`.

- **Видимость:** все неразобранные заявки практики и заявки, ставшие
  работами этого менеджера. Заявка, ставшая чужой работой, не видна.
- **Отбор:**
  - «Страница сайта»: Посадочная, Аспирантам, Студентам, Компаниям, Из
    кабинета;
  - «Состояние»: Новая, В работе, Отработана, ждёт ответа, Консультация
    проведена, Договор заключён, Отказ, Спам;
  - поиск по имени, почте, телефону, теме.
- По 50 на страницу, новые сверху. Отзывы в перечень не входят.
- **«Выгрузить в таблицу»** — CSV по тому же отбору, 15 колонок, включая
  контакт, текст и согласие. Каждая выгрузка пишется в журнал.

### 5.2. Карточка заявки

Адрес `/cabinet/manage/leads/{id}`.

**Шапка:**

- имя, источник, состояние, дата;
- кнопки «Написать» (почта) или «Позвонить», «Позвонить по доп.
  телефону».

**Содержание:**

- тема и текст обращения (или «Обращение без текста: человек оставил
  только контакт»);
- научный руководитель, вуз, направление, контактный телефон, желаемый
  срок;
- приложенные файлы — скачивание пишется в журнал;
- строка о согласии на обработку ПДн;
- пометка машинной заявки, если приём её распознал.

**Работа с заявкой:**

- смена состояния: Новая, В работе, Отработана, ждёт ответа, Консультация
  проведена, Спам; ручная пометка спама — этой кнопкой;
- внутренние комментарии («Их видят только руководитель и менеджеры»);
- «Исправить сведения заявки».

**«Одобрить и создать работу».** Поля:

- «Название работы» — по умолчанию тема заявки;
- «Тип сопровождения» — в списке у типа есть пометка «· есть шаблон
  этапов»;
- отметка «Применить шаблон этапов, если он есть у выбранного типа».

Что происходит после одобрения:

- **куратором становится тот, кто одобрил**: поля выбора куратора нет;
- создаётся работа с кодом `PD-ГГГГ-NNN`; дата начала — сегодня по Москве;
- если в заявке есть почта, создаётся учётная запись клиента, в неё
  переносится согласие;
- клиенту уходит письмо «Заявка принята: работа {код}» без ссылки входа;
- файлы заявки переходят в материалы работы;
- менеджер попадает на экран созданной работы.

**«Отклонить заявку»:**

- причина обязательна;
- если в заявке есть почта, причина уходит заявителю письмом «Ответ на
  заявку ProDisser»;
- заявке-спаму и заявке без почты письма нет; подсказка предлагает
  сообщить причину звонком.

## 6. Новый заказ (вручную)

Адрес `/cabinet/manage/orders/new` (`lib/cabinet/manual-order.ts`). Вход —
кнопка «Новый заказ» на экране «Работы практики». Экран для заказов,
пришедших звонком или письмом.

**Поля:**

- обязательные: заказчик (ФИО), вид работы, название;
- необязательные: почта, телефон, описание, дата заказа (по умолчанию
  сегодня), дедлайн, стоимость, оплачено;
- состояние — в работе, остановлена или завершена.

Поле «Куратор» есть только у руководителя; менеджер всегда становится
куратором сам.

**Что происходит:**

- карточка клиента ищется по ФИО во всей практике, иначе создаётся новая;
- при стоимости больше нуля создаются договор и транш «Поступление при
  заведении заказа» на оплаченную сумму;
- учётная запись клиенту не заводится, писем не уходит.

## 7. «Работы практики» — перечень своих работ

Адрес `/cabinet/projects`. Видны только работы, где менеджер куратор.

**Вкладки и поиск** появляются при числе работ больше 8:

- «Действующие» — в действии и приостановленные;
- «Ждут клиента» — этап ждёт материалов или согласования;
- «Завершённые» — завершённые и отменённые;
- «Все»;
- поиск по коду, названию, теме и ФИО клиента.

По 20 на страницу.

**В карточке работы в перечне:**

- тип сопровождения, название, тема;
- состояние, если работа не в действии;
- «План работ не заведён…», если этапов нет;
- полоса готовности и что ждут по этапу;
- свёртка «Этапы · N»;
- срок с пометкой «прошёл»;
- строка: «X из N этапов · N материалов · N новых сообщений · клиент».

**Сверху** — блок этапов, ждущих клиента, по работам вне текущей страницы.
Там же кнопка «Новый заказ».

## 8. Карточка работы

Адрес `/cabinet/projects/{код}`.

**Шапка и «О работе».** Название, срок, состояние (если работа не в
действии). В свёртке: тип, тема, срок работы, куратор, краткое описание.

**Шкала готовности:**

- процент завершённых этапов;
- чей ход — одной подписью на шкале, этапе и «Требует внимания»: «Ход за
  вами: этап не начат.», «Ход за экспертом: этап в работе.» (без эксперта —
  «Ход за вами: назначьте эксперта.»), «Ход за клиентом: ждём материалов.»,
  «Ход за клиентом: этап на согласовании.»; руководителю по чужой работе —
  «Ход за куратором…» (Р-288);
- сроки этапа и работы с пометкой «прошёл».

**«План работ»:**

- этапы с подписями состояний для сотрудников, сроки, причина ожидания,
  краткое описание;
- свёртка «Правка этапа» — только у работы в действии: «Название этапа»,
  «Суть выполнения» (видна клиенту), «Срок этапа».

**«Переписка с клиентом»:**

- последние 8 сообщений, поле «Написать клиенту»;
- сообщение с контактами помечено «похоже на передачу контактов»;
- ссылка «вся переписка».

**«История работы»** — до 200 событий: этапы, версии, состояние работы,
назначение исполнителя, смена куратора.

**«Строка книги заказов»** — для работ, перенесённых из книги: исходные
поля строки, включая стоимость и оплату.

**«Управление работой»:**

1. **Новый этап** — только у работы в действии: название, суть выполнения,
   срок. Этап встаёт последним в состоянии «Не начат». Шаблон этапов
   применяется только при одобрении заявки.
2. **Состояние работы.** Переходы:

   | Из | В |
   |---|---|
   | В действии | приостановить, завершить, отменить |
   | Приостановлена | возобновить, завершить, отменить |
   | Завершена | возобновить |
   | Отменена | возобновить |

   - У завершённой и отменённой работы ставится сегодняшняя дата закрытия.
   - Этапы при смене состояния не меняются. Срок согласования этапа на
     паузе стоит: остаток рабочих дней сохраняется, при возобновлении срок
     отсчитывается от дня возобновления (Р-290).
   - Клиент об этом не уведомляется.
3. **Карточка работы:** название, тема, короткое описание (видно клиенту),
   срок работы, «Срок согласования этапа, рабочих дней» — от 5 до 20, по
   умолчанию 5; новое число действует со следующей сдачи этапа (Р-290).
4. **Исполнитель:**
   - выбор из всех действующих экспертов; у эксперта без договора
     поручения пометка «— без договора поручения»;
   - такой исполнитель доступа к материалам не получит, пока руководитель
     не отметит договор.
5. **Клиент:** ФИО, почта, телефон, способы связи и его предпочтения
   («Звонок куратора», «Полное сопровождение» и т. д.).
6. **«Оплаты и документы»** — экран оплат, только просмотр (раздел 11).

Передачи работы другому куратору у менеджера нет.

**Отказ действия** «Управления работой» показывается у той формы, которая
отказала: свёртка раскрыта, поля заполнены введённым, причина — над
полями (Р-279). Пределы: название работы — 300 знаков, тема — 500, короткое
описание — 2 000.

## 9. Этап

Адрес `/cabinet/stages/{id}`.

**Шапка:** название, состояние, исполнитель, срок, «прошёл N дней назад».
У работы не в действии — плашка «Работа …: этапы не меняются…».

**«Что сделать сейчас»** — у работы в действии:

- подсказка по состоянию этапа, чей ход, просрочка, число материалов и
  замечаний на модерации;
- «Перенести срок этапа» с подсказкой «Срок видит клиент: перенос без
  причины в переписке он читает как срыв».

**Переходы этапа** (`lib/cabinet/stage-state.ts`):

| Из | В |
|---|---|
| Не начат | В работе |
| В работе | Ждёт материалов клиента; На согласовании у клиента |
| Ждёт материалов клиента | В работе; На согласовании у клиента |
| На согласовании у клиента | Завершён (согласование); В работе |
| Завершён | — |

**Правила переходов:**

- «Ждёт материалов клиента» — только с обязательной «Причиной остановки».
  Её читает клиент, и ему уходит письмо «Этап «…» ждёт ваших материалов».
- «На согласовании у клиента» — только если к этапу приложен материал;
  иначе кнопки нет. Клиенту уходит письмо «Этап «…» готов к
  согласованию».
- **Согласовать за клиента** — кнопка «Согласовать этап». Согласование
  пишется в журнал.

**Материалы и версии:**

- скачивание версий;
- «Загрузить следующую версию», «Приложить новый материал»;
- проверка имени файла на контакты к менеджеру не применяется.

**Модерация замечаний:**

- замечание специалиста ждёт публикации всегда; замечание клиента — если
  в нём есть контакты (пометка «есть контакты»);
- кнопки «Опубликовать клиенту» / «Опубликовать» и «Отклонить» с
  необязательной причиной: её увидит автор;
- разобранное замечание второй раз не разбирается;
- публикация замечания специалиста отправляет клиенту письмо «Эксперт
  оставил замечание по материалу»;
- комментарий самого менеджера публикуется сразу.

## 10. Материалы и переписка

**Материалы работы** (`/cabinet/projects/{код}/materials`):

- все материалы, привязка к этапу, версии, авторы, число замечаний;
- загрузка новой версии и нового материала;
- у материала вне этапов — замечания к версиям с кнопками «Опубликовать» и
  «Отклонить»; дело модерации с «Требует внимания» ведёт сюда, к
  материалу (Р-284);
- удалить материал нельзя никому.

**Скачивание:** по правам, с записью в журнал доступа к файлам. Ограничение
размера — 50 МБ.

**Переписка** (`/cabinet/projects/{код}/messages`):

- подзаголовок «с клиентом · {ФИО}»;
- до 10 000 знаков, вложений нет;
- открытие экрана переписки куратором отмечает сообщения клиента
  прочитанными; короткая лента на карточке работы отметок не ставит;
- сообщение с телефоном, почтой, `@именем` или ссылкой на мессенджер не
  блокируется, а помечается и попадает в реестр «Контакты в переписке»;
- специалист в переписке не участвует.

## 11. Оплаты и документы

Адрес `/cabinet/projects/{код}/payments`. **Только просмотр.**

**Видно:**

- договор: номер и дата;
- «Сумма договора», «Получено», «Осталось оплатить», процент оплаты;
- транши в состояниях «ожидается», «выставлен счёт», «оплачен»: сроки,
  дата оплаты, счета и акты;
- документы по договору.

**Скрыто:**

- маржа и вознаграждение специалиста;
- списанные и сторнированные транши;
- пояснения «не разнесено по траншам» и «работа отменена — остаток учтён
  в потерях»;
- все формы изменения: договор, транши и документы ведёт руководитель.

## 12. Реестры и «Управление»

**«Управление»** (`/cabinet/manage/tools`). Менеджеру доступны «Работы
практики», «Все заявки», «Реестры». Ниже карточка «Спросить руководителя
практики»: поле «В чём нужна помощь», кнопка «Отправить вопрос». Вопрос
уходит всем руководителям уведомлением «Вопрос от куратора: {ФИО}».

**Реестры** (`/cabinet/manage/registry`):

- **«Клиенты»** — только клиенты его работ: вуз и специальность,
  контакты, число работ, последний вход. Поиск — при числе клиентов
  больше 20.
- **«Эксперты»** — все действующие эксперты: степень, специализация,
  отметка о договоре поручения, загрузка (только по его работам).
  Контактов экспертов нет.
- **«Контакты в переписке»** — последние 50 помеченных сообщений по его
  работам.

## 13. Настройки и уведомления

Экран `/cabinet/settings` — тот же, что у клиента:

- способы связи;
- каналы почта / Telegram;
- привязка Telegram.

Дополнительно у менеджера есть таблица **«Какое событие каким каналом»**:
по каждому событию отдельно письмом и/или в Telegram. Строка, снятая со
всех каналов, означает «не сообщать».

**Что получает менеджер:**

| Событие | Когда | Тема | Можно настроить |
|---|---|---|---|
| Сообщение клиента | клиент написал; повторно не шлётся, пока прежнее не прочитано | «Новое сообщение по работе {код}» (без текста) | да |
| Новая версия материала | материал загрузил клиент или специалист | «Новая версия материала: …» | да |
| Новая заявка из кабинета | клиент подал заявку из кабинета; всем менеджерам и руководителям | «Новая заявка из кабинета» | да |
| Новая заявка с сайта | заявка с сайта (не спам) | письмо на общий ящик заявок и сигнал в общий Telegram-чат со ссылкой на карточку заявки | вне кабинета: зависит от доступа к ящику и чату |
| Этап согласован | согласовал клиент или руководитель за клиента; о своём согласовании куратор письма не получает | «Этап «…» согласован» со ссылкой на этап | да (Р-282) |
| Этап принят по сроку | срок согласования истёк при включённом автозакрытии (п. 7.3 оферты) | «Этап «…» принят по истечении срока» со ссылкой на этап | да, той же строкой «Этап согласован или принят по сроку» (Р-290) |
| Клиент вернул этап с замечаниями | клиент нажал «Вернуть с замечаниями» | «Клиент вернул этап «…» с замечаниями» — без текста замечаний, со ссылкой на этап | да (Р-282) |

**Что менеджер не получает:**

- новое замечание специалиста на модерации — видно только в «Требует
  внимания»;
- приближение сроков — напоминание уходит только клиенту;
- назначение куратором руководителем.

Сигнал в Telegram несёт только событие и код, без содержания.

## 15. Расхождения и незавершённые места

Ниже — наблюдения по коду, не исправленные на 03.10.2026. По каждому
нужно решение: исправить или оставить как есть.

**Процесс и уведомления**

1. **О согласовании этапа клиентом менеджер не узнаёт уведомлением.**
   Видно только в кабинете.
2. **О новом замечании специалиста на модерации уведомления нет.** Оно
   появляется только в «Требует внимания».
3. **Напоминание о сроке уходит только клиенту.**
   - Менеджеру и специалисту оно не приходит.
   - Для этапа «В работе», где ход за специалистом, письмо получает
     клиент.
4. **Ближайшие сроки менеджеру не показываются.**
   - Перечень «срок в ближайшие 7 дней» считается, но выводится только в
     блоке руководителя «Ближайшие сроки и деньги».
5. **Смена состояния работы не уведомляет клиента.** Это относится к
   приостановке, завершению и отмене.
6. **Специалиста не уведомляют.** Ни о назначении на работу, ни о
   публикации или отклонении его замечания.
7. **Смену состояния работы нельзя проверить перед применением.**
   - В списке «Состояние работы» нет пустого пункта, первым стоит,
     например, «Приостановить».
   - Кнопка «Сменить состояние» применяет выбранное сразу, без
     подтверждения.

**Ошибки и экраны**

8. **Отказы показывают общий экран «Сбой».** Так происходит при:
   - сохранении карточки работы;
   - смене состояния работы;
   - назначении исполнителя;
   - передаче куратора.

   У этих действий нет перехвата ошибок (`app/cabinet/actions.ts`,
   строки ≈374–415). Например, «Экспертом может быть только действующий
   эксперт» приводит к экрану «Сбой» вместо причины.
9. **Замечание к материалу вне этапа нельзя разобрать.**
   - Ссылка из «Требует внимания» ведёт на общий перечень работ.
   - На экране материалов кнопок модерации нет.
   - Замечание остаётся «ожидает публикации» без способа его решить.
10. **Исполнитель не виден ни в шапке этапа, ни в «О работе».**
    - Строка «исполнитель …» на экране этапа читает поле этапа, которое
      кабинет не заполняет.
    - Назначенного исполнителя видно только в выпадающем списке
      «Исполнитель».
11. **Карточка согласования обращается к менеджеру как к клиенту.** Её
    текст — «Этап ждёт вашего согласования».
12. **Подписи «чей ход» расходятся.** На экране этапа и в «Требует
    внимания» — «ход за вами: этап не начат», на шкале — «Ход за
    практикой».
13. **«Перенести срок этапа» может откатить чужую правку.** Форма
    отправляет название и суть этапа на момент открытия экрана.
14. **Сырые названия состояний в ошибке.** Текст: «Переход этапа из
    «IN_PROGRESS» в «DONE» не предусмотрен».
15. **Причина смены состояния этапа нигде не показывается.** Она
    сохраняется, но в «Истории работы» её нет. Событие «Назначен
    исполнитель» — без имени.
16. **Описание этапа не выводится на экране этапа.** Видно только на
    карточке работы, в две строки.

**Права и границы**

17. **Менеджер не может открыть клиенту вход.** Это может только
    руководитель. При этом:
    - страница входа без почты советует клиенту «Напишите куратору…»;
    - экран «Новый заказ» отсылает к «Учётным записям», которые менеджеру
      недоступны.
18. **«Новый заказ» заводит договор и оплату при запрете на деньги.**
    Менеджер вносит сумму договора и полученную оплату, хотя изменение
    денег закрыто для всех, кроме руководителя.
19. **Совпадение по ФИО затрагивает чужие работы.** «Новый заказ» ищет
    клиента по ФИО во всей практике: заказ может лечь в карточку клиента
    чужих работ и дописать её контакты.
20. **Закрытые и приостановленные работы заморожены не полностью.**
    - Загрузка, комментарии и модерация работают.
    - Карточка работы правится.
    - Заморожены только этапы.
21. **Состав плана менять нельзя.**
    - Нет удаления и переупорядочивания этапов.
    - Нет возврата завершённого этапа.
    - Текст раздела «Управление» при этом обещает «правку состава
      этапов».
22. **Шаблоны этапов на карточке работы применить нельзя.** Шаблон
    применяется только при одобрении заявки; правит шаблоны руководитель.
23. **«Строка книги заказов» показывает менеджеру деньги.** Стоимость и
    оплата видны, хотя денежный контур менеджеру закрыт. На экране оплат
    списанное скрыто, и цифры могут не сходиться.

**Тексты и подсказки**

24. **Названия не соответствуют видимости.**
    - Перечень и пункт «Управление» называются «Работы практики», а
      менеджер видит только свои работы.
    - После входа он попадает не на «Требует внимания».
25. **Карточка «Как этим пользоваться» в «Управлении» не учитывает роль.**
    Менеджеру советуют разделы, которые ему недоступны: очередь
    уведомлений, справочники, отчёт за период.
26. **Карточка «Спросить руководителя» обещает ответ «тем каналом, который
    он выбрал».** Механизма ответа в кабинете нет.
27. **Экран уведомлений написан для клиента.**
    - Тексты: «Куратор видит этот список…», «…письмом менеджеру».
    - В таблице правил есть строка «Куратор просит помощи (руководителю)»,
      которая менеджеру не приходит.
28. **Подсказка ведёт на недоступный экран.** Отклонённая заявка с
    недоставленным письмом советует «Повторить отправку… на экране очереди
    уведомлений».
29. **Перенос из заявки неполон.**
    - Заявка только с телефоном создаёт новую карточку клиента без
      проверки на дубль.
    - Доп. телефон и организация из заявки в карточку не переносятся.
30. **На «Требует внимания» у очереди заявок нет листания.** Видны первые
    20; заявки в состояниях «Отработана, ждёт ответа» и «Консультация
    проведена» в эту очередь не входят.
