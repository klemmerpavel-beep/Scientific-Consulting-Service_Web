# Подключение облачного хранилища: пошагово и простым языком

Для руководителя практики. Здесь всё, что осталось сделать, чтобы связка
«сайт → личный кабинет → облачное хранилище» работала сама, без вашего
участия, и чтобы Claude мог читать и править файлы на Диске по вашим
поручениям. Решение — Р-266.

Время: около 30 минут, всё делается в браузере и одной командой на сервере.

---

## Часть 0. Что уже работает само

| Что | Как |
|---|---|
| Сайт prodisser.ru | принимает заявки со всех форм, кладёт их в базу на сервере в России |
| Личный кабинет | заявка сразу видна в «Все заявки» и в очереди; руководитель одобряет — заводится работа, клиенту — учётная запись |
| Выкат | после каждого слияния сайт обновляется сам, с копией базы и откатом при сбое |
| Наблюдение | GitHub по расписанию (на деле раз в несколько часов) проверяет сайт, кабинет и сертификат; при сбое приходит письмо |
| Расписание на сервере | рассылка уведомлений кабинета — раз в минуту; выгрузка на Диск — в :00; перенос книги с Диска — в :30. Ждут только доступа к Диску |
| Копии базы | каждую ночь |

Не хватает трёх подключений: Диск (эта инструкция), почта и Telegram
(часть 5). Без почты кабинет работает, но ссылки входа сотрудникам и
клиентам выдаёте вы вручную (часть 6).

---

## Часть 1. Учётная запись Яндекса под Диск

Нужна учётная запись, чей Диск станет хранилищем практики.

- **Лучше всего:** Яндекс 360 для бизнеса на ООО «РУСДРОН», запись
  `info@prodisser.ru`. У тарифа организации есть договор поручения
  обработки персональных данных — на такой Диск можно класть книгу
  заказов с ФИО клиентов.
- **Для проверки сегодня:** отдельная бесплатная запись, например
  `prodisser.disk@yandex.ru`. Не ваш личный Диск: доступ будет ко всему
  Диску записи. Персональных данных клиентов туда не кладите — сайт
  выгружает таблицы в обезличенном режиме (часть 3, `SCOPE=anon`).

**Пароль приложения** — отдельный пароль только для файлов, его можно
отозвать в любой момент, не трогая основной:

1. Войдите в эту запись на id.yandex.ru.
2. «Безопасность» → «Пароли приложений» → «Создать пароль».
3. Тип — «Файлы (WebDAV)», название — «ProDisser».
4. Скопируйте пароль — он показывается один раз. Никому не пересылайте,
   в чат тоже.

## Часть 2. Доступ для Claude — не нужен

Сайту и кабинету достаточно доступа сервера (часть 3). Пароль приложения
в настройки облачной среды Claude не вносится: переменные среды видны
всем, кто ею пользуется, и форма среды прямо запрещает класть в них
секреты (решение Р-271). Проверку Диска Claude делает по отчёту
`chain-check.sh` из журнала выката (часть 4) — в нём «вход принят» или
причина отказа, без паролей и содержимого.

Если прямой доступ всё же понадобится (разовая правка файлов на Диске из
сессии Claude), для него заводится отдельный пароль приложения, который
отзывается сразу после работы. Окружение правится на экране новой
сессии claude.ai/code: значок облака у поля ввода → **Cloud** → строка
окружения → значок правки или **Add cloud environment**; сетевой доступ
**Custom** с хостом `webdav.yandex.ru`, переменные `YANDEX_DISK_USER` и
`YANDEX_DISK_PASSWORD`. Тогда `node tools/disk.mjs check` проверяет
доступ, а перед каждой записью прежняя версия файла кладётся в
`ProDisser/Архив/`.

## Часть 3. Доступ для сервера — чтобы сайт и кабинет работали с Диском сами

Тот же логин и пароль приложения вписываются на сервере. После этого
выгрузка таблиц и перенос книги идут по расписанию без вас.

1. На компьютере откройте PowerShell и войдите на сервер:
   ```
   ssh root@85.193.84.95
   ```
2. Откройте настройки:
   ```
   nano /opt/prodisser/deploy/.env
   ```
3. Найдите строки `YANDEX_DISK_…` (стрелками) и заполните. Если строки
   нет — допишите в конец:
   ```
   YANDEX_DISK_USER=prodisser.disk@yandex.ru
   YANDEX_DISK_PASSWORD=пароль приложения
   YANDEX_DISK_FOLDER=ProDisser
   YANDEX_DISK_SCOPE=anon
   ```
   `anon` — таблицы уходят без имён и контактов; `all` — таблицы полностью
   и файлы работ. На тестовый период руководитель решил выгружать всё
   (`all`) и на бесплатный Диск, приняв правовой риск (решение Р-271);
   после проверки — переход на Яндекс 360 заменой логина и пароля.
4. Если книга заказов лежит на этом Диске (`ProDisser/Учёт/Книга заказов.xlsx`),
   допишите ещё строку — книга будет сама переезжать в кабинет раз в час:
   ```
   BOOK_PULL_PATH=Учёт/Книга заказов.xlsx
   ```
   Без этой строки книга загружается вручную: «Управление» → «Перенос книги
   заказов».
5. Сохраните: `Ctrl+O`, `Enter`, `Ctrl+X`.
6. Перезапустите приложение и сделайте первую выгрузку:
   ```
   cd /opt/prodisser
   docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d
   /opt/prodisser/deploy/yandex-sync.sh
   ```
   Последняя строка должна быть «готово: в зеркале 14 файлов».

Дальше — само: выгрузка каждый час в :00, книга с Диска в кабинет в :30.
В кабинете это видно на экране «Управление → Зеркало на облачном диске».

## Часть 4. Проверка всей связки

GitHub → репозиторий → **Actions** → «Выкат на боевой сервер» → **Run
workflow**. В конце журнала — отчёт по строке на звено:

- `[ок]` — работает;
- `[—]` — не включено (например, почта, пока её нет);
- `[!]` — сломано, с подсказкой, что поправить. «Яндекс не принял логин
  или пароль приложения (код 401)» — пароль введён с ошибкой или отозван.

Или просто попросите Claude: «проверь, что всё работает».

## Часть 5. Почта и Telegram — чтобы заказы отрабатывались без вас

**Telegram (10 минут, бесплатно):** сигнал о каждой новой заявке на телефон.

1. В Telegram найдите `@BotFather` → `/newbot` → имя «ProDisser заявки» →
   получите токен.
2. Напишите своему боту любое сообщение.
3. `@getidsbot` → узнайте свой Chat ID (число).
4. На сервере в `deploy/.env`: `TELEGRAM_BOT_TOKEN=…`, `TELEGRAM_CHAT_ID=…`,
   затем команда `docker compose … up -d` из части 3, шаг 6.

**Почта (с Яндекс 360):** полное содержание заявки на `info@prodisser.ru`,
письма клиентам о ходе работы и ссылки входа — автоматически. Настройки —
`docs/DEPLOY.md`, раздел 5е.

## Часть 6. Как добавить менеджера или эксперта

1. Войдите в кабинет: prodisser.ru/cabinet.
2. «Управление» → **«Учётные записи»**.
3. Раскройте «Завести учётную запись»: имя и отчество, почта, роль
   («Эксперт» или «Менеджер») → «Завести».
4. **Пока почта не подключена:** там же, внизу экрана, «Выдать ссылку
   входа» → выберите человека → «Выдать ссылку» → скопируйте и передайте
   ему (мессенджер, звонок). Ссылка действует два часа и срабатывает один
   раз; сессия после входа — до 90 дней.
5. **Когда почта подключена:** человек сам открывает prodisser.ru/cabinet,
   вводит свою почту и получает ссылку письмом.

Роль меняется там же; «Приостановить» мгновенно закрывает доступ. Если за
человеком есть открытые работы, кабинет попросит сначала передать их
другому куратору или эксперту (в карточке работы, «Управление работой»).

## Часть 7. Как проходит заказ

1. Клиент оставляет заявку на сайте → она в базе и в кабинете, «Все
   заявки»; вам — сигнал в Telegram (если подключён).
2. Менеджер или вы открываете заявку и одобряете → заводится работа,
   клиенту — учётная запись. Куратором становится тот, кто одобрил;
   менеджер видит только свои работы, поэтому одобренную вами работу
   передайте ему: карточка работы → «Управление работой» → куратор.
3. В карточке работы — этапы со сроками, эксперт, договор и оплаты.
4. Клиент в кабинете видит ход работы, материалы по версиям, переписку.
5. Каждый час таблицы работ, этапов и оплат уходят на Диск.
6. Руководитель видит деньги, итоги по годам и отчёт за период.

Подробно по экранам — `docs/GUIDE-CABINET.md`.
