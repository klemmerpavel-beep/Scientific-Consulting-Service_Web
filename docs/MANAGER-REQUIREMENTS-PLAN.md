## 4. План по требованиям

### Блокирует открытие

#### М-01 · Причина отказа на месте вместо «Сбоя»

**Сверка с кодом.**

- `saveProject`, `changeProjectStatus`, `setExpert`, `setManager`
  (`app/cabinet/actions.ts:374–415`) работают без перехвата.
- Сырые названия состояний — из `lib/cabinet/projects.ts:827`.
- `ActionError` на карточке стоит вверху, а формы — в свёрнутой «Управление
  работой». `Disclosure` не умеет открываться сам.

**Делается:**

- четыре действия обёрнуты в `withError`, возврат с якорем на блок формы;
- `Disclosure` получает `open` и `id`, `ActionError` — место вывода (`slot`);
  причина показывается рядом с формой, свёртка раскрыта;
- **черновик формы.** Вторая одноразовая cookie `pd_form`: `HttpOnly`, путь
  `/cabinet`, 5 минут, та же метка, что у причины (Р-243). Поля берут из неё
  `defaultValue`. Если текст длиннее предела cookie (~1500 знаков), черновик
  не сохраняется, а причина говорит об этом;
- пределы длины полей карточки работы — по образцу Р-242;
- в ошибке перехода этапа — подписи состояний: для сотрудников — служебные,
  для клиента — клиентские.

**Схема:** нет. **Права:** нет.
**Объём:** M (1,5).
**Проверки:**

- `action-flash.test.ts`: черновик, предел, все четыре действия идут через
  `withError`;
- `stage-guards.db.test.ts`: русские подписи;
- на базе: «недействующий эксперт» → причина на экране работы.

**Решения:** Р-242, Р-243 дополняются; новое Р. Механизм черновика нужен
М-09 и М-18, поэтому М-01 выходит раньше них.

#### М-02 · Замечания к материалу вне этапа

**Сверка с кодом.**

- Ссылка дела вне этапа ведёт на `/cabinet/projects`
  (`app/cabinet/manage/page.tsx:325`).
- Дела группируются по названию материала (`materials.ts:576`): одноимённые
  материалы разных работ сливаются в одно дело.
- Возврат после решения ведёт на `/cabinet/stages/` с пустым id — это 404.
- Текст замечаний к материалу вне этапа не видит никто — ни практика, ни
  клиент.

**Делается:**

- в `pendingComments` — код работы и id материала, группировка по id;
- документы оплат и закрытые работы (М-10) дел не дают;
- на «Материалах работы» — свёртка замечаний у материала: текст, автор,
  кнопки «Опубликовать» и «Отклонить»;
- ссылка дела — `/cabinet/projects/{код}/materials#material-{id}`, возврат
  после решения — туда же;
- клиент видит опубликованные замечания на этом экране.

**Схема:** нет. **Права:** нет (`COMMENT_MODERATE`).
**Объём:** S–M (1).
**Проверки:** на базе — две одноимённые записи в двух работах дают два
дела; ссылка ведёт на материал; повторное решение — «уже разобрано»;
снимки.

**Решения:** Р-183 дополняется; новое Р.

#### М-03 · «Открыть клиенту вход»

**Сверка с кодом.**

- Выдачу ссылки (`issueAccessLink`, `lib/cabinet/admin.ts:71–109`) имеет
  только руководитель; пределов частоты нет, прежние ссылки не гасятся.
- `createUser` заводит учётную запись без привязки к карточке клиента.
- «Новый заказ» ведёт на `?created=1`, который карточка работы не читает.

**Делается.** Служба `openClientAccess(actor, projectId)` в `lib`:

- `ensure` с работой. Без работы `isPracticeFor` разрешил бы менеджеру
  любое действие (`access.ts:128`), поэтому ссылка на работу обязательна;
- отказы с причиной:
  - карточка обезличена или сведена;
  - почта — сотрудника;
  - учётная запись закрыта;
  - почта принадлежит клиенту с другой карточкой — «сведите карточки»,
    это делает руководитель;
- клиент без карточки привязывается; записи нет — создаётся (ОМ-4) и
  привязывается;
- ссылка на 2 часа через общий с руководителем помощник, с тем же экраном
  «Войти» и маской адреса; прежние непогашенные ручные ссылки этого
  клиента гасятся;
- журнал: `USER_CREATED`, `ACCESS_LINK_ISSUED` с работой;
- руководителю — уведомление о выдаче менеджером (ОМ-3);
- пределы: 3 ссылки на клиента в сутки, 20 на сотрудника в сутки;
- сессия, открытая ссылкой сотрудника, помечается. Согласование этапа в
  ней записывается с этой пометкой (ОМ-3).

На экранах:

- кнопка в блоке «Клиент» карточки работы — `AccessLink` в режиме одного
  адресата; новой части в браузере нет;
- после «Нового заказа» с почтой — плашка с той же кнопкой;
