# Демонстрационный стенд на Vercel

Быстрый способ получить живую ссылку: посмотреть сайт с телефона,
показать коллегам, прокликать формы. **Это не боевое размещение.**
Боевое — `docs/DEPLOY.md`, на российской площадке.

## Почему стенд, а не запуск

Три причины, по которым Vercel не годится как постоянный дом проекта.

**Персональные данные уезжают за границу.** Заявка — это имя и контакт.
Любая бесплатная база под Vercel (Supabase, Neon, Vercel Postgres) стоит
в США или ЕС. Часть 5 статьи 18 152-ФЗ требует, чтобы база с данными
граждан России находилась в России. Пока в базу идут только пробные
заявки — вопроса нет. Как только по ссылке придёт настоящий человек и
оставит настоящий телефон, это нарушение.

**Бесплатный тариф Vercel Hobby разрешён только для некоммерческого
использования.** Сайт действующего ООО под него не подходит: аккаунт
могут закрыть, и уведомления об этом не будет.

**Доступ из России к `*.vercel.app` не гарантирован.** Ровно то
требование, ради которого выбиралась площадка, здесь и не выполняется.

Поэтому стенд закрыт от поисковиков: `NEXT_PUBLIC_DEMO_STAND=1` даёт
`noindex, nofollow` на всех страницах и `Disallow: /` в `robots.txt`.
Без этого временный адрес попадёт в выдачу и будет годами перебивать
боевой.

## Порядок

### 1 · База данных

Подойдёт Supabase или Neon, бесплатного тарифа хватает с запасом.

**Supabase:** supabase.com → New project → регион любой (на скорость
стенда не влияет) → задать пароль базы. Затем Project Settings →
Database → Connection string, оттуда нужны две строки:

| Что | Где взять | Куда |
|---|---|---|
| Connection pooling, режим **Transaction**, порт 6543 | вкладка Connection pooling | `DATABASE_URL` |
| Direct connection, порт 5432 | вкладка Connection string → URI | `DIRECT_URL` |

Две строки нужны потому, что бессерверные вызовы Vercel живут коротко и
плодят подключения — их принимает пулер. А миграции идут в обход пулера:
он не пропускает служебные команды, которыми Prisma меняет схему.

**Neon:** аналогично, в консоли даются `pooled` и `unpooled` строки.

### 2 · Накатить схему

Один раз, со своей машины:

```bash
cd app
npm ci
DIRECT_URL="<прямая строка подключения>" npx prisma migrate deploy
```

Проверить, что применилось:

```bash
DIRECT_URL="<прямая строка>" npx prisma migrate status
```

Должно ответить `Database schema is up to date!`.

**Без командной строки.** У Supabase есть окно SQL — тогда схему можно
вставить туда. Готовый текст печатает:

```bash
cd app && npm ci && npm run schema:sql > schema.sql
```

Содержимое `schema.sql` целиком вставить в Supabase → SQL Editor → Run.
Скрипт собирает текст из тех же миграций, что и `migrate deploy`, и
дописывает отметку о применении — без неё Prisma при следующем
развёртывании решит, что база пустая, и попробует создать таблицы заново.

### 3 · Проект на Vercel

vercel.com → Add New → Project → Import Git Repository →
`klemmerpavel-beep/Scientific-Consulting-Service_Web`.

Приложение лежит не в корне репозитория, поэтому одна настройка
обязательна:

> **Root Directory** → `app`

Остальное Vercel определит сам: Next.js, `npm install`, `npm run build`.
Самодостаточная сборка на Vercel отключается автоматически — платформа
выставляет переменную `VERCEL`, и `next.config.mjs` это учитывает.

### 4 · Переменные окружения

В Vercel: Settings → Environment Variables. Минимум для рабочего стенда:

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | строка через пулер, порт 6543 |
| `DIRECT_URL` | прямая строка, порт 5432 |
| `NEXT_PUBLIC_SITE_URL` | адрес, который выдаст Vercel, например `https://prodisser.vercel.app` |
| `NEXT_PUBLIC_DEMO_STAND` | `1` |

`NEXT_PUBLIC_DEMO_STAND` читается **при сборке**, а не при запуске:
после её добавления нужен повторный деплой, иначе стенд останется
открытым для поисковиков.

Необязательно, если хочется проверить уведомления:

| Переменная | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | бот от @BotFather и адрес чата |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`, `LEAD_MAIL_TO` | доступ к почте |

Без них приём заявок работает: отказ канала доставки записывается в
журнал и не роняет заявку.

### 5 · Проверить

```
https://<адрес>/api/health     → {"ok":true,"db":true}
https://<адрес>/robots.txt     → Disallow: /
```

Затем открыть `/`, `/main`, `/students`, `/business` и отправить по
заявке с каждой. В Supabase: Table Editor → таблица `Lead` — там должны
появиться записи с отметками согласия.

## Чем стенд отличается от боевого сайта

**Ограничение частоты заявок работает слабее.** Счётчик обращений живёт
в памяти процесса (`src/app/api/lead/route.ts`), а Vercel поднимает
процессы по мере нагрузки — у каждого счётчик свой. Пятнадцать заявок
за пять минут с одного адреса превращаются в пятнадцать на процесс.
Ловушка для роботов и проверка времени заполнения при этом работают
как обычно. На своём сервере процесс один и ограничение точное.

**Первый заход после простоя медленнее.** Бесплатный тариф усыпляет
функции; холодный старт добавляет секунду-две к первой заявке.

**Резервных копий нет.** `deploy/backup.sh` рассчитан на свою базу.
Для стенда это неважно — данные в нём пробные.

## Когда переезжать на боевую площадку

Как только ссылку планируется показать кому-то, кроме команды. Порядок
в `docs/DEPLOY.md`: контейнеры, база в России, TLS, резервные копии.
Перед открытием подаётся уведомление в Роскомнадзор об обработке
персональных данных — решение Р-06 в `docs/DECISIONS.md`.

После переезда стенд нужно удалить, а не оставить «на всякий случай»:
два живых адреса одного сайта путают и посетителей, и поисковики.
