# ProDisser — сайт научного консалтинга

Публичный сайт научно-консультационного сервиса **ProDisser**
(коммерческое обозначение ООО «РУСДРОН»).

Семь страниц, приём заявок с сохранением в базу на территории России,
уведомление ответственного в Telegram и на почту.

**Витрина проекта:**
[klemmerpavel-beep.github.io/Scientific-Consulting-Service_Web](https://klemmerpavel-beep.github.io/Scientific-Consulting-Service_Web/)
— семь страниц со всеми переходами, без сервера: заявки не отправляются,
персональные данные не сохраняются. Там же
[прототип личного кабинета](https://klemmerpavel-beep.github.io/Scientific-Consulting-Service_Web/cabinet/)
— связанный обход экранов под четырьмя ролями (клиент, эксперт, менеджер,
руководитель) на обезличенных данных практики. Если `github.io` недоступен,
прототип выкладывается второй площадкой: `node tools/cabinet-portable.mjs
<каталог>` собирает переносимую копию, в которой каждая ссылка указывает на
файл (решение Р-144). Третья площадка — свой домен:
[prodisser.ru/cabinet-preview/](https://prodisser.ru/cabinet-preview/)
(решение Р-174).

> Website of a Russian academic-consulting service. Next.js 16 + React 19,
> Prisma 7 + PostgreSQL. Pages are generated from `design/*.dc.html` layouts
> by `tools/dc-to-tsx.mjs` and must not be edited by hand — see
> [CONTRIBUTING.md](CONTRIBUTING.md). Documentation is in Russian.

## Быстрый старт

Нужны **Node 22** (та же версия в CI), **PostgreSQL 16** и npm. Docker — только
для развёртывания на сервере.

```bash
cd app
npm ci
cp .env.example .env          # заполнить, см. таблицу ниже
npx prisma generate
npx prisma migrate deploy
npm run dev                   # http://localhost:3000
```

Обязательные переменные окружения:

| Переменная | Зачем | Без неё |
|---|---|---|
| `DATABASE_URL` | подключение к базе заявок | приложение не стартует |
| `NEXT_PUBLIC_SITE_URL` | canonical, Open Graph, карта сайта | карта сайта пустая, canonical отсутствует |
| `SESSION_SECRET` | свёртки ссылок входа и сессий кабинета, не короче 32 знаков | кабинет показывает «Раздел готовится» (Р-153), сайт работает |
| `CABINET_STORAGE_DIR` | каталог материалов кабинета | то же |

Необязательные: `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — уведомление о
заявке; `SMTP_*` и `LEAD_MAIL_TO` — дублирующий канал почтой;
`NEXT_PUBLIC_DEMO_STAND=1` — закрыть стенд от индексации;
`NEXT_PUBLIC_METRIKA_ID` — номер счётчика посещаемости, без него счётчика нет
и политика содержимого остаётся закрытой; `CABINET_CRON_SECRET` — секрет
маршрута рассылки уведомлений кабинета `/cabinet/api/outbox`, без него
рассылка выключена и уведомления ждут в очереди. Полный список с
пояснениями — в `app/.env.example`.

Проверки перед отправкой правки:

```bash
npm run typecheck     # проверка типов
npm test              # проверки без базы
npm run test:db       # то же вместе с проверками на PostgreSQL
npm run build         # рабочая сборка
npm run build:preview # статическая витрина
```

Автоматические проверки — `node --test` по `app/tests/`: `npm test` даёт
2187 проверок без базы, `npm run test:db` — 2304, из них 117 на настоящей
PostgreSQL (адрес базы берётся из `app/.env`). CI гоняет `npm test` на
каждом запросе на слияние (`.github/workflows/ci.yml`). Линтера нет:
`next lint` объявлен устаревшим, отдельная настройка ESLint не заводилась.
Приёмка облика ручная и инструментальная, порядок — в `docs/PLAN.md`,
раздел 5; проверочные ширины сайта — 360, 390, 414, 480, 768, 1024 и
1440 px (`docs/DESIGN-SYSTEM.md`, раздел 6), снимки кабинета обходятся на
1100, 1280, 1440, 1920 и 390 px.

Развёртывание на сервере — `docs/DEPLOY.md`.
Витрина проекта для показа — `docs/PREVIEW.md`.
План дальнейшей работы — `docs/PLAN.md`.

## Как менять внешний вид

**Правится макет, а не сгенерированный компонент.** Страницы в
`app/src/components/pages/` собираются из `design/*.dc.html` конвертером и
перезаписываются при каждом переносе:

```bash
# имена макета и компонента совпадают
node tools/dc-to-tsx.mjs design/StartPage.dc.html \
  app/src/components/pages/StartPage.tsx StartPage landing

# а здесь не совпадают: MainPage -> PostgradPage
node tools/dc-to-tsx.mjs design/MainPage.dc.html \
  app/src/components/pages/PostgradPage.tsx PostgradPage postgrad
```

Команда для всех восьми макетов сразу — в `CONTRIBUTING.md`.

Сборка в CI проверяет, что перенос воспроизводим: если сгенерированный
компонент разошёлся с макетом, значит правку внесли не туда. Там же
проверяется, что `design/assets` и `app/public/assets` не разошлись.

Оформление — палитра, шкала кеглей, компоненты, движение — описано в
`docs/DESIGN-SYSTEM.md`.

Логика класса переносится дословно — `DCLogic` это `React.Component` без
`render`. Конвертируется только шаблон: подстановки, циклы, условия,
инлайновые стили и состояния наведения.

## Приём заявок

Заявка сначала сохраняется в базу, потом доставляется. Запись без доставки —
это задержка ответа; доставка без записи — потерянный клиент и отсутствующий
журнал согласия. Отказ канала доставки записывается в журнал и не роняет
приём.

Вместе с заявкой хранится журнал согласий: отметки, редакция текста согласия,
адрес и клиент. Через год нужно уметь показать, с чем именно согласился
заявитель.

Требование ч. 5 ст. 18 152-ФЗ: база с персональными данными граждан РФ
находится на территории России. Обеспечивается выбором площадки —
`docs/DECISIONS.md`, Р-06.

## Ключевое правило проекта

**Компания не пишет работы за клиента.** Продукт — экспертиза и сопровождение.
Любая формулировка, читаемая как «напишем за вас», — дефект. Прямое «мы не
пишем» тоже не используется: тон остаётся лояльным, роль описывается через
действия сервиса.

Ни одного обещания решения диссовета, кафедры, комиссии, редакции, фонда,
Роспатента или налогового органа. Предмет обязательства — соответствие
требованиям на дату подачи.

Полный свод — `design/HANDOFF.md`, раздел «Правила, которые нельзя нарушать».
Решения по спорным вопросам — `docs/DECISIONS.md`.
